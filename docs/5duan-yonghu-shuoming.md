| 你是谁 | 安装文件 | 桌面图标 | 登录 |

| 普通同学（课表、下单、广场等） | `SunshineCampus-User-1.2.7.apk` | 阳光校园 | **学号 + 教务密码** |

### 0.2 怎么安装

1. 把对应 `.apk` 拷到手机，或拖进 MuMu / 雷电等模拟器。  
2. 系统提示「未知来源」时允许安装。  
3. **学生端**包名 `com.sunshinecampus.app`，可覆盖旧学生端；其它四端是独立包名，不会顶替学生端。

### 0.3 登录差异

| 端 | 开屏 |
| --- | --- |
| **学生用户端** | 学号 + 正方教务密码（可先进入 App，课表稍后同步） |
| **管理 / 骑手 / 商家 / 档口** | 手机号验证码，或手机号 + App 密码 |

- 工作四端**不要填学号**。  
- 会话保存在本机；卸载即清。

### 0.4 更新怎么来

| 类型 | 路径 | 何时用 |
| --- | --- | --- |
| **界面热更新** | Capgo（装好 1.2.7+ 壳后自动） | 只改 H5/React 界面与业务逻辑 |
| **整包 APK** | 设置 → 检查更新（读线上 `update.json`） | 改原生插件、权限、签名、壳配置等 |

热更一般**下次冷启动**生效；整包按提示下载对应角色 APK。五端版本号建议对齐。

## 1. 学生用户端（User）

**文件：** `SunshineCampus-User-1.2.7.apk`  
**给谁用：** 在校同学日常使用。  
**登录：** 学号 + 教务密码。

### 怎么用

1. 打开后进**首页**（底栏：首页 · 服务 · 发布 · 消息 · 广场 · 我的）。  
2. **学业** — 服务 → 学业中心 / 课表查询；同步课表、成绩、考试；成绩可按学年筛选、导出。  
3. **生活** — 广场发帖、互助、二手、食堂点餐、小店街；中间绿色 **+** 发布。  
4. **想当档口主 / 骑手 / 开小店** — 我的 → 设置 → **角色工作台** 提交申请；通过后再装对应工作端，用**手机号**登录同一账号。

### 小提示

- 校外同步教务：先开 WebVPN（学业中心入口有链接）。  
- 上课 / 考试提醒：勿静音；允许通知与震动。

## 7. 常见问题

**Q：骑手/商家为什么不能用学号？**  
A：只有学生用户端用学号；工作端统一手机号。

**Q：装了骑手端却提示还不是骑手？**  
A：先申请并等审核通过；手机号必须与申请一致。

**Q：管理端没有「成员治理」？**  
A：只有站长有；请用 `15329826989` 登录管理端。

**Q：热更新了界面，还要不要下 APK？**  
A：纯界面改动一般不用；改了原生 / 权限 / 签名必须下新 APK。

**Q：五端要不要一起升？**  
A：建议同一 versionName（如都 1.2.7），避免行为不一致。

## 8. 开发者：维护、更新、后续上架

### 8.1 工程位置与五端包名

| 壳 | applicationId | 产物名 |
| --- | --- | --- |
| User | `com.sunshinecampus.app` | `SunshineCampus-User-*.apk` |
| Admin | `com.sunshinecampus.app.admin` | `SunshineCampus-Admin-*.apk` |
| Rider | `com.sunshinecampus.app.rider` | `SunshineCampus-Rider-*.apk` |
| Shop | `com.sunshinecampus.app.shop` | `SunshineCampus-Shop-*.apk` |
| Stall | `com.sunshinecampus.app.stall` | `SunshineCampus-Stall-*.apk` |

源码：`Desktop\xm-main`。Capacitor `appId` / Capgo App ID 均为 `com.sunshinecampus.app`（五端共享同一 Web 包与热更通道）。

### 8.2 版本号必须四处对齐

发版前同步改：

1. `package.json` → `version`  
2. `android/app/build.gradle` → `versionName` / `versionCode`（每次整包 +1）  
3. `src/lib/app-update.ts` → `APP_VERSION`  
4. `capacitor.config.ts` → `plugins.CapacitorUpdater.version`  
5. `public/update.json` → `latestVersion` / `latestBuild` / 各 flavor 下载 URL  
6. `tools/release-5duan.bat` / `tools/capgo-upload.bat` 里的版本字面量  

### 8.3 日常发版流程

**A. 只改界面（推荐热更）**

```bat
cd Desktop\xm-main
tools\capgo-upload.bat
```

上传 `dist-app` 到 Capgo `production`。已装 1.2.7+ 壳的用户会后台下载，下次启动生效。  
密钥在本地 `.env.capgo`（勿提交 git）。说明见 `docs/release/capgo.md`。

**B. 改了原生 / 要发整包**

```bat
cd Desktop\xm-main
tools\release-5duan.bat
```

脚本会：**先清空** `Desktop\5duan` 再写入本版五个 APK + 本说明书，避免新旧文件混在一起。  
然后把 APK 上传到托管目录（与 `update.json` 里 URL 一致），并部署更新后的 `update.json`。

**C. 推 GitHub Release（可选）**

网络通畅（可开 Clash `7897`）后：`tools\push-github-5duan.bat`。

### 8.4 签名与加固（上架前必读）

| 项 | 现状 / 注意 |
| --- | --- |
| 签名文件 | `android/keystore/sunshine-release.jks`（本地开发用；上架前务必换成正式密钥并备份） |
| 签名哈希 | freeRASP 已写入当前 jks 哈希；换正式签名后必须改 app-security 配置里的 hash |
| R8 | Release 已开混淆；改 ProGuard 后要全五端烟测登录与桥接 |
| freeRASP | 现策略：模拟器 / 非商店安装只告警不杀进程，方便校园侧载与 MuMu |
| 上架后建议 | `killOnBypass: true`；收紧非官方商店策略；补齐各应用商店包名白名单 |

详见 `docs/release/hardening-1.2.6.md`。

### 8.5 应用商店上架检查清单

1. **包名锁定**：学生端 `com.sunshinecampus.app` 一旦上架不可改；其它四端若也上架，各自 applicationId 同样锁定。  
2. **正式签名**：新建生产 keystore，备份密码与 jks；所有后续更新必须同一签名。  
3. **隐私与权限**：清单里只保留实际使用的权限；准备隐私政策 URL、权限用途说明。  
4. **软著 / 备案**：应用名「阳光校园」、包名、图标与材料一致。  
5. **内容安全**：管理端审核链路保持可用；用户协议 / 社区规范入口可见。  
6. **支付与提现**：若上架渠道要求，核对支付资质与资金流说明。  
7. **热更新合规**：对照目标商店条款；敏感时期可关掉自动热更、只发审核过的整包。  
8. **多包策略**：五端是五个 applicationId——商店上是五个应用。若只上架学生端，工作端可继续校园侧载 + `update.json`。  
9. **测试账号**：给学生学号测试号、管理端手机号、说明「工作端需角色审核」。  
10. **Capgo / 云函数**：生产 API Key、CloudBase 环境与域名写进运维备忘；`.env.capgo` 不进仓库。

### 8.6 登录与站长约定（勿随意改）

- 仅 User 走校园学号门禁；Admin / Rider / Shop / Stall 走手机号门禁。  
- 引导超级管理员：用户名档案 `2023120448`，手机 `15329826989`。  
- 改站长手机或引导逻辑前，先确认库里角色与手机绑定，再发版。

### 8.7 网络与常见构建坑

- Capgo / GitHub / Maven 超时：开系统或终端代理后再构建。  
- Capgo updater 依赖 `patches/...patch` + `postinstall`；重装依赖后需 `npm install`。  
- Capgo 的 `VITE_*` 由 vite / build-multiplatform 从 `.env.capgo` 注入。  
- 发 `5duan` 前务必清空旧文件（`release-5duan.bat` 已自动清空），避免新旧版本混放。
