# 哦狐学习工具完善方案

状态：需求梳理与本地开发中。先在本地逐页验收；不执行热更新、打包或发布。

## 目标与现状

借鉴 CampusHub 的通知整理、课程入口和科目包思路，结合哦狐现有账号、待办和课表，减少遗漏作业和反复寻找课程资料的成本。参考资料：[CampusHub 项目说明](https://github.com/Tim-Chuck/CampusHub#readme)。该仓库目前未发现明确的项目级开源许可，本项目按功能独立实现，不复制其源码；第三方字体或依赖另行核对许可。

现有哦狐能力：课表教务同步及本机缓存、ICS 导出、账号待办和到期提醒。课表分享码与共同空闲有部分底层代码，尚未确认页面及后台完整接通，不能视为已交付功能。课程网址、课件和作业入口的独立整理功能尚未发现。

参考项目的科目包以 JSON 文件导入导出，并非持续自动同步；其完整 ICS 解析依赖服务端。不要在宣传中承诺哦狐是无账号、完全本地或任何功能都已离线可用。

## 第一阶段：粘贴通知生成待办

### 已确认

- 待办页提供显眼的“粘贴通知生成待办”入口，首页通过已有常用功能进入待办。
- 通知文本只在设备上识别，不调用 AI、服务器或第三方解析服务。识别结果先预览，可修改标题、截止日期、时间和作业链接。
- 一个通知可包含多个候选；用户逐项勾选、确认后才保存。无法可靠拆分时明确提示，允许自行调整，不能编造任务。
- 只把确认后的标题、截止时间和链接保存到现有账号待办；不保存原始通知全文。待办沿用账号同步与既有提醒设置，不修改提醒开关或提前时间。
- 日期已识别但时间缺失时，保留日期、时间留空并提示确认；不得暗中填 23:59 或排定一个虚假的提醒。现有数据库只存精确时间，因此在未明确时刻时需请用户补充，或明确选择不设置截止提醒；不能以假时间写入。
- 链接保存前可修改，保存后显示“打开作业”。仅允许经过校验的 HTTP(S) 链接；不自动访问、预取或上传原始通知。链接本身随用户确认保存到账号，可能包含个人信息，界面应清楚提示。

### 识别和交互

1. 用户主动粘贴通知；提供字数上限、清空和关闭入口。输入保留在当前窗口内存，不记录日志、分析埋点或持久草稿。
2. 本机识别常见明确日期、今天/明天/后天、本周/下周星期、中文或数字时间，以及 HTTP(S) 链接；优先提示邻近“截止、截至、最晚、提交”的日期。
3. 多个时间或链接提供选择；模糊星期、缺少年份、已经过去、无效日期、无法拆分等显示提示。缺少标题和时间保持待确认状态；不支持的表达应由用户手动修改。
4. 每个候选独立勾选并编辑；确认按钮保存前检查标题、日期时刻组合与链接。没有选中的候选不创建。保存中避免重复点击；逐条写入失败时保留失败项和错误原因，已成功项不可在重试时再次创建。
5. 账号变更、退出、关闭窗口和组件卸载清除原文与未保存预览；迟到的异步结果不能写入或显示到另一个账号。只在实际保存成功后报告成功。
6. 保存后复用待办原有列表、提醒与账号数据。链接在列表内作为独立可访问操作，不能嵌套在编辑按钮中；无法打开时提供可复制的地址。

### 数据兼容

`src/lib/todo.ts` 的现有待办字段为 title、note、due_at 等，没有单独链接列。正式实现需选择兼容方案：若利用 note 保存结构化链接，应区分旧备注与新数据、支持编辑且不覆盖旧文本；若新增独立字段，则必须提供数据库迁移、权限、旧版本兼容和未部署时的错误处理。不要假设线上已有新字段。

代码入口：`src/pages/TodoPage.tsx`、`src/components/NoticeTodoSheet.tsx`、`src/lib/notice-parser.ts`、`src/lib/notice-todo-batch.ts`、`src/lib/todo.ts` 与 `src/lib/todo-remind.ts`。本机识别、预览和确认保存的代码已接入，链接使用兼容旧数据的 note 字段；本地解析及批量保存测试通过。真实账号同步、跨设备、提醒送达及真机体验仍需验收。

### 验收

- 空通知、超长输入、不含日期、多任务编号、模糊日期、无效日期、跨年和北京时间边界；多个链接、非法链接、带凭据的链接。
- 输入没有时间不得伪造截止时间或提醒。预览编辑内容与最终保存一致；原文和未勾选项不出现在请求、数据库、日志及持久缓存中。
- 多条保存时有成功、有失败，再重试不得重复创建；离线、未登录、权限失败、慢请求、账号切换与重复点击均有清晰反馈。
- 已有普通待办的新增、编辑、备注、完成、删除、排序和提醒不回归；Android 键盘不遮挡保存操作，长文本在窄屏可滚动，支持可见焦点和减少动态。
- 单元测试覆盖解析和结果校验；组件/端到端测试覆盖实际确认保存与失败恢复。真实账号同步、跨设备与后台提醒需单独验收，不由本地模拟代替。

## 第二阶段：课程资料与作业入口

### 已确认

- 先从我的课表读取课程建议，也允许手动新增课程；课表建议必须属于当前账号，不能读取上一个账号的缓存。
- 每门课可以整理网址、标题、备注和附件，覆盖课程网站、网课、学习资料与作业提交入口。
- 网址与附件随账号云端保存，其他设备登录同一账号后可同步。不能只写 localStorage 却宣称跨设备同步。
- 附件第一版支持 PDF、Word、PPT、Excel 和图片，单个文件最多 20 MB。具体扩展名、真实文件类型校验及账号总容量需在服务端明确配置。
- 删除课程时，将课程、资料和附件一起移入回收站，30 天内可恢复；恢复时保留原有关联。到期后清理需真实可靠，界面不可在清理尚未发生时宣称文件已永久删除。
- 单独删除附件也进入回收站，支持 30 天内恢复。
- 每个账号的附件总存储额度为 1 GB；上传前和服务端写入时均需检查额度，并明确显示已用与剩余空间。并发上传也不能突破额度。
- 已打开过并成功缓存的资料支持离线查看；离线修改先保存在当前账号的本地队列，联网后同步，并显示待同步、同步失败与冲突状态。无法缓存或尚未打开的附件应明确提示需要联网。

### 待用户确认

- 视频、压缩包及账号总存储空间是否支持。
- 离线缓存容量与清理策略。
- 科目包下一阶段怎样分享：文件导入还是链接/二维码；是否附带附件、是否允许持续更新。

### 建议实现方式

- 独立“课程资料”页面，课程列表可筛选搜索；课程详情按网站、资料、作业入口分组，支持添加、编辑、删除与打开。
- 现有课表 `TtRow` 没有稳定课程 ID。用归一化课程名和教师生成建议，用户确认是否合并同名课程，资料分组使用独立稳定 ID；课表重新同步、改名、换学期或暂时无课时，不得自动删除已保存资料。
- 为课程、资源及附件建立账号隔离的数据模型；所有读写强制校验账号身份与行级权限。定义数据库迁移、索引、权限和回滚，不能复用其他用户可写的字段充当资料库。
- 当前 `src/lib/chat-image.ts` 只支持经压缩的小图片，不能直接当作 PDF/Office 私有附件服务。附件需设计私有存储、类型/大小检查、上传进度、取消/重试、下载权限及删除；上传失败不创建虚假记录，数据库写入失败时处理已上传的孤儿文件。
- 回收站需要保存删除时间与恢复期限，使用服务端可信时间判断；30 天到期后的元数据和文件清理由可靠的服务端任务执行，清理失败需重试。恢复与到期清理并发时必须避免资料指向已删除文件。
- 跨设备同步要处理加载/空/错误、离线编辑冲突、账号切换和重复上传；旧数据与跨账号权限必须验证。上线数据库和存储配置前只做本地准备，必要时提示未接通。
- 离线缓存和待同步队列按账号严格隔离；退出和更换账号时不得将前一账号内容展示或提交给新账号。缓存只包含已成功打开的数据，提供清理入口；缓存空间不足、文件未缓存和离线同步冲突应明确提示。冲突不可静默覆盖，保留可供用户比较的版本并等待选择。

### 验收

- 课表未绑定、同步失败、同名课程、跨学期、手动课程以及课表刷新后资料不丢失；账号 A/B 切换无数据串用。
- 支持的文件格式、大小边界、上传中断、取消、重试、重复提交、下载鉴权、跨设备同步和删除状态一致。
- 离线重启后已缓存资料可用，未缓存附件明确显示不可用；断网修改、重连提交、冲突选择、缓存空间不足及账号切换均不得丢数据或串号。
- 删除课程后 30 天内可恢复课程及附件；到期清理、清理失败重试、恢复与清理并发时状态一致。
- 非本人无权读取或删除课程及私有附件；链接输入及文件名安全处理；真实服务未部署时不能显示虚假成功。

## 第三阶段：科目包分享与其他候选

在课程资料稳定后再设计科目包：导出前预览内容；默认不带密码、个人数据、通知原文或带敏感参数的链接；导入先检查大小、类型和数据格式，预览并确认，再按用户选择合并，冲突与失败可见。附件是否纳入分享及对方是否能持续看到更新，需用户明确选择，不能把文件复制描述为自动同步。

可进一步研究 ICS 导入预览、课程入口用途标签和学期归档。多人课表、分享码和共同空闲先审查页面及服务端实际状态，再决定是否继续建设，不能把未接通的底层函数当成已上线功能。

## 执行顺序

1. 完成通知识别、待办预览与保存闭环，在本地和真实账号上分开验收。
2. 与用户确定课程附件的格式、容量及删除规则，设计数据和私有存储，再完成课程资料管理与跨设备同步。
3. 逐项确认科目包、ICS 等后续需求。先本地验收，再按用户明确指示进行安装包、热更新或发布。
