## 已复现并修复

1. JSON根类型／字段类型、非法OCR重试参数触发500：统一拒绝异常对象、限制字段类型与长度、8KB请求体、重试最多8次。
2. 来源IP伪造：默认忽略任意转发头，仅明确配置可信代理网段和跳数时按链右端取值。尚未猜测生产网关网段；共享出口可能共享IP限额，后续需按实际拓扑核验。
3. 旧 `/api/schedule` 未执行与新版相同的限流：已统一全局、IP、账号限额和Retry-After。
4. 学业响应缺少明确禁止缓存：所有API响应，包括错误，增加no-store；上游异常不再记录原始堆栈，避免异常URL带出个人参数。
5. RSA填充使用普通PRNG：改为系统随机数；验证重置普通PRNG种子不能重复密文填充。

原始基线36项中33失败、3通过；其中2项是Schemathesis响应头表示的测试错误，已纠正，不能把全部失败都算漏洞。其余失败包含同一缺陷的多组样例，不能按失败数声称发现33个独立漏洞。

## 线上交付

后端已发布为 `2.4.1-security150`，CloudRun `jou-api-010` 承担100%流量。保持0.5CPU／1GB、单实例、8090端口。只打包10个经审阅的运行文件，不包含测试Schema路由、测试工具、密钥文件或本机日志。

发布前一次无凭据非法JSON请求返回500；发布后5个低频公网检查通过：健康版本正确、异常JSON／非法OCR参数返回400、超长请求返回413，并均带no-store。没有在公网尝试真实登录或向学校发送凭据。证据：`security150-backend-deployment.json`。

线上数据库再次以合成普通身份／匿名身份检查：13张私人表无跨用户结果，认证表、私有取证、旧提权和账号搜索被拒绝。事务回滚，未修改业务数据。这不是手机JWT端到端验收。

## 实用边界

本轮没有证明骚扰电话的来源，也不能凭扫描通过排除历史泄露。没有进行生产破坏性扫描、拒绝服务压测、短信轰炸、账号爆破或导出私人数据。公网低频探测不替代带真实测试账号的端到端验证。历史日志、完整备份、云告警及其他GitHub账号仍按事件记录继续核实。

复跑：`tools/jou-api/test_security_attacks.py`、`tools/phone-privacy.test.mjs`（设置 `OHU_SECURITY_FUZZ=1` 启用生成测试）、`tools/verify-phone-lockdown.mjs`。依赖工具版本见本机隔离环境，不以全局安装环境结果代替。
