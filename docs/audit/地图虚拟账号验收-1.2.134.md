# 地图虚拟账号验收 · 1.2.134

日期：2026-10-23。测试对象：连云港地图、学生本地点、地点提交与管理员审核、私密/公开打卡。

## 测试环境与账号

这是独立的本地验收环境，不是正式云账号登录。用测试学生甲、测试学生乙、测试管理员及游客身份运行项目的真实页面和地图业务模块。底层使用 PGlite 的 PostgreSQL 引擎，执行原始 `campus-map-132.sql` 和 `campus-map-city-134.sql`，并启用行级访问规则。

本地 `auth.uid()` 与管理员身份映射用于模拟认证上下文；没有验证真实 CloudBase 账号登录、云端网络或生产环境管理员映射。生产数据库尚未应用地图迁移。

测试页：`http://127.0.0.1:43128/campus-map`。顶部可切换测试身份，无需输入密码。虚拟数据只在本地测试数据库中，重启测试服务后重置；本地点保存在该测试站点的浏览器存储中。测试页与虚拟账号不会进入 APK/IPA。

## 已完成的检查

- 测试学生甲创建虚拟地点：先保存本机，可选提交待审核。
- 待审核申请仅本人及管理员可读；另一名学生不能审核或冒名提交。
- 管理员通过后生成共享地点；重复处理不会重复生成；学生乙能在列表中查看。
- 驳回的地点不会进入共享地图。
- 私密打卡仅本人及按规则授权的管理员可读；公开打卡审核通过后才对其他学生可见。
- 游客不能提交地点；直接写入“已通过”状态被数据库拒绝。
- 本地点刷新后仍存在，按账号隔离，云端范围补齐后仍可读取。
- 反复执行迁移不会重复插入种子地点或丢失学生已通过的地点。
- 浏览器实际操作走完提交、审核、换账号查看；真实底图及地点标记已显示。

自动测试：`node --test tools/campus-map-qa.test.mjs`，9 项通过。发布流程回归：`npm run test:release`，63 项通过。静态检查没有错误，仍有已有模式的 React effect 性能建议。

## 本次测试修复

1. MapLibre 的解析工作文件在构建后路径失效，导致白底地图：改为由构建工具生成并引用独立资源。
2. 地点筛选、增加标点会重建地图并跳回初始视角：改为更新地图数据源。
3. 本地点只按学校存储，同一设备换账号会混用：改为账号与学校共同隔离。旧版无归属记录不会自动分配给某个账号。
4. 地点审核通过后再新增本地点会重复显示：统一合并本机和共享地点并去重。

```powershell
node --test tools/campus-map-qa.test.mjs
node tools/map-qa-server.mjs
```
