# 朋友圈修复与验证（1.2.130）

学生端原页面缺少发布按钮，全局发布也没有朋友圈项；空态却提示点击底部发布。评论和图片查看按钮没有实际动作。页面只在首次挂载读取，游客登录后不重新加载；读取失败被展示为“还没有动态”。这些均已在实际源码确认并修复。

现在全局“发布”和朋友圈页都可打开朋友圈发布表单，支持文字、最多 9 张图片及好友可见／登录用户可见／仅自己可见。动态正文和评论按钮打开详情，图片支持大图与前后切换，评论支持读取与发送，点赞与本人删除有实际动作。失败保留草稿并明确提示；登录按钮直接打开 App 登录面板。页面、上传和写入异步结果都绑定账号会话，退出或切换账号不回填旧结果。

## 已部署数据库修复

元数据检查确认生产环境已有 moments、moments_likes、moments_comments 及所需字段，问题不是缺表。原好友动态读取策略仅匹配 user_uid=本人 的单一方向，而接受好友的现有逻辑只建立一条边。新的策略允许关系任一方向存在，同时要求双方申请已接受；不将待申请关系当成好友。删除好友边后，即使保留历史已接受申请也不能继续看好友动态。

原点赞／评论读取策略为 true，插入也只校验操作者字段。新策略要求父动态对当前账号可见，私密动态仍只有本人能看。子表只依赖父动态，父动态只依赖好友与申请，不引入 RLS 循环。不添加 security definer，不修改表授权，不删除或重写动态、评论、赞及账号数据。

- 固定事务脚本：`docs/sql/moments-visibility-130.sql`
- 应用前元数据与授权备份：`docs/audit/moments-schema-before-130.json`
- 应用记录：`docs/audit/moments-policy-deployed-130.json`，RequestId `a0339d8e-4f0f-47d2-8711-d704849cd657`，AffectedRows 0。
- 应用后元数据：`docs/audit/moments-schema-readonly-2026-10-21.json`
- 生产 authenticated 角色＋合成 claims 的三表查询计划检查：`docs/audit/moments-role-check-130.json`。均使用 WHERE false，不读取个人业务行。
- 生产 PostgreSQL 用真实线上 policy 表达式和内联合成 VALUES 验证 9 种可见性组合：`docs/audit/moments-policy-matrix-130.json`。包含私密本人／陌生人、登录公开、好友双向、待申请／拒绝、无关和已无好友边场景。

## 验证层级

`tools/moments-session.test.mjs` 的 9 项隔离测试通过：游客无请求、发布校验和成功确认、读错保留错误、A→B→A 迟到回包阻断、同账号新会话重建页面、点赞重试与本人删除、评论确认、无效编号和策略边界。`npx tsc -b --pretty false` 通过。

`.codex/moments130-ui-qa.cjs` 在实际 React 页面及路由上运行隔离 API 和身份替身：390／1024 宽、浅／深色四组均通过。覆盖发布入口、上传预览、可见范围、成功刷新、详情、评论、图片大图、点赞、加载失败、退出、重新登录、发布失败保留草稿。报告 `.codex/qa/moments130-ui-report.json`；详情和错误状态截图均已打开检查。没有真实云端发帖、评论或上传媒体，也未使用真实个人凭据。

数据库角色检查和合成矩阵不能替代两名真实用户的端到端好友、私密动态与媒体访问测试；本轮没有宣称完成这类实账号验收。生产数据库已实际应用策略，前端需要随 1.2.130 APK／热更新发布后生效。

图片沿用现有公共图片存储桶。动态和评论的可见范围由数据库策略保护，但已取得图片直链的人仍能访问该图片；本轮未迁移媒体到私有存储，也不将动态可见范围等同于媒体访问鉴权。
