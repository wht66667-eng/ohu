# 哦狐手机号风险核查与加固记录

日期：2026-11-02（Asia/Shanghai）。最终用户要求：保留手机号注册，加强数据库防护。

## 已确认的缺陷

1. 生产库的 `trg_bootstrap_named_super_admin` 和 `ensure_bootstrap_super_admin()` 仍能依据可编辑昵称提升管理员权限。这是实际权限漏洞；并非“所有表没开 RLS”。账号搜索 RPC 本来校验站长，但旧提权逻辑破坏了这个前提。
2. 二手、任务、失物招领、互助等主表允许普通登录身份读取所有行，行里包含联系方式。公开视图虽已剥离联系字段，脚本仍能绕开界面直接访问主表。
3. 普通活动报名会静默复制当前登录手机号，晨跑报名默认填入登录手机号。店铺审批还会将申请联系方式复制到公开店铺资料。
4. 配送待接单池的读取策略允许已审核骑手在接单前读取客户联系方式。

没有证据证明上述漏洞已经被利用，也没有证据将用户收到的骚扰电话与某一次数据库访问对应。没有读取或导出用户手机号、短信验证码、密码或会话令牌。

## 已上线的数据库措施

`docs/sql/phone-privacy-lockdown-149.sql` 于 08:20Z 原子执行：

- 删除昵称提权触发器，撤销旧提权 RPC 的客户端调用权限；函数变成不执行提权的兼容实现。
- 从现有管理员授权登记与 Auth 的真实身份建立私有 UID 固定绑定。管理员判定同时要求绑定、角色标记与未封禁状态。改昵称或占用已改名的用户名不能继承旧身份。
- 3 个未能与授权登记对应的历史权限标记已隔离；只撤销权限，不删除账号。原标记与原函数定义保存在 `ohu_security` 私有 schema，供站长复核；不能据此认定这些账号是攻击者。
- 关闭匿名／普通身份对 Auth 表的读取、公有 schema 建对象、删除本人权限档案，以及直接执行触发器函数的权限。
- 账号搜索仅经固定绑定的有效站长可用，3–64 字、字面子串匹配、最多 10 条；空串和 SQL 通配符不能用来列全库。

`docs/sql/contact-privacy-149.sql` 于 08:24Z 原子执行：

- 六张联系／私人记录主表增加 RESTRICTIVE SELECT 策略，普通人只能读取本人；经授权管理员沿原业务权限管理。
- 公开内容视图不包含联系字段；增加作者 UID 以维持站内私信。本人管理仍读原主表。
- 活动主办人改走脱敏名单 RPC，不返回报名人的电话或宿舍信息。
- 公开店铺视图不再返回联系方式；骑手接单前不能直接读客户私人订单行。
- 账号数据和历史联系方式没有被批量删除或改写。

## 客户端修改

- 活动报名不再自动复制登录手机号；晨跑联系方式默认为空且可选。
- 读取他人二手／任务详情时使用不含电话的公开内容视图，维持站内私信。失败查询不扩大读取范围。
- 无权读联系方式时明确提示站内联系，不把提示文本复制成“联系方式”。

数据库保护不依赖客户端升级。旧客户端的直接联系方式读取会被服务器阻止；新版界面会解释并引导私信。现有旧商城配送池将不再返回尚未接单的私人订单行；若未来重新启用该模块，应先接入仅含非敏感字段的接单池接口，不能放回宽松策略。
