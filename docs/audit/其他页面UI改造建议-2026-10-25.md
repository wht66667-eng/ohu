# 哦狐其他页面 UI 改造建议

## 文档目的

首页已经采用“狐狸吉祥物 + 森林绿 + 暖象牙白 + 狐狸橙”的视觉方向。本文件将这套方向延伸到其他页面，作为后续逐页改造和验收依据。

本文件是设计与实施建议，不代表本轮已经改完其他页面。所有页面应继续使用现有账号、权限、CloudBase 数据和路由，不用演示数据替代真实接口。

## 统一设计基线

### 视觉变量

| 用途 | 建议值 |
|---|---|
| 主色 | `#1F5B3A` 森林绿 |
| 页面底色 | `#FFF8EB` 暖象牙白 |
| 强调色 | `#FF8A3D` 狐狸橙 |
| 辅助浅绿 | `#E6F1E8` |
| 主要文字 | `#183326` |
| 次要文字 | `#6F7D73` |
| 警示色 | `#C9553D` |
| 页面左右边距 | 14–16px |
| 普通卡片圆角 | 18–22px |
| 小控件圆角 | 12–16px |
| 主要点击区域 | 至少44×44px |

### 页面结构

其他页面统一使用“标题区 → 主内容 → 状态反馈 → 底部导航/操作”的结构。页面顶部不再堆叠多个相同权重的按钮；一个页面只保留一个明确的主操作，其余操作使用次级按钮、图标按钮或底部面板承接。

首页的狐狸装饰只在需要解释、鼓励或空状态时出现。课表、地图和聊天等高频功能页面要优先保证信息密度和可读性，狐狸插画不能遮挡课程、地点、消息或输入框。

统一复用现有 `PageHeader`、`DialogLayer`、`StateViews`、`MessageEntry`、`TabBar` 和 `OhuArtwork`。图标优先使用 `public/brand/ohu-original` 中的透明裁切资源；没有对应原稿图标时使用线性图标，不再使用带白底的截图裁片。

## 页面改造建议

### 1. 课表与课表登录

涉及文件：

- `src/pages/schedule/ScheduleHome.tsx`
- `src/pages/schedule/ScheduleHome.module.css`
- `src/pages/schedule/SchoolScheduleGuide.tsx`

建议把课表页做成“今日课程优先”的信息页：顶部显示周次、日期和校区，下面使用森林绿时间轴展示课程。当前课程用狐狸橙边框或橙色状态点突出，已结束课程降低透明度，下一节课显示“距离上课还有多久”。

登录状态要分成三种明确状态：未登录、正在加载、已绑定但同步失败。未登录时仍可浏览说明和学校入口，点击“同步课表”才进入对应登录页；同步失败时保留上次经过账号校验的快照，并显示重试入口，不能把失败误显示成“今天没课”。

多校查询建议统一成同一张登录卡：学校名称、账号输入、密码输入、登录按钮和“需要帮助？”入口。学校差异只放在登录说明和请求适配层，不要为每所学校制作一套完全不同的页面。

提醒设置放在课表页的次级入口中，使用“通知、铃声、震动、提前分钟数”四个明确控件。权限未开启时显示系统权限引导；提醒过期后不再补发半小时前的课程通知，但保留历史记录。

### 2. 地图与校园打卡

涉及文件：

- `src/pages/CampusMapPage.tsx`
- `src/pages/CampusMapPage.module.css`
- `src/pages/AdminCampusMapPane.tsx`

地图页建议以地图为主画布，顶部只保留搜索、校区/连云港范围切换和定位按钮。地点详情使用底部抽屉，内容顺序为名称、分类、图片、地址、营业或开放信息、导航按钮。

“美食、好玩、打卡”使用统一的彩色筛选胶囊：美食使用橙色、好玩使用绿色、打卡使用黄色。用户新增地点时，先用当前定位作为默认坐标，也可以在地图上点选微调；图片上传放在表单第一屏，最多3张并显示压缩进度。

用户提交的地点显示“待审核”状态，只对提交者可见；管理员通过后才进入公开地图。管理员审核页要能看到图片、坐标、提交者、分类和重复地点提示。

点击导航时先尝试打开高德 App，未安装再进入官方网页；步行、骑行、驾车作为底部选择项，不放在地图上长期占位。

### 3. 服务页与学习工具

涉及文件：

- `src/pages/ServicesPage.tsx`
- `src/pages/services.module.css`
- `src/pages/english/*`
- `src/pages/study/*`
- `src/pages/words/*`

服务页沿用首页“常用功能”卡片，但扩展为分组入口：学习、校园生活、工具、社交。每组最多两行，图标采用透明裁切的统一尺寸，标题使用真实功能名称，未接通的功能显示为不可用或隐藏，不能使用假入口。

英语、单词、专注和目标页应共享同一套学习状态卡：今日目标、已完成数量、连续天数和开始按钮。学习页面的主操作统一放在卡片底部，避免多个橙色按钮同时争夺焦点。

### 4. 校园广场与朋友圈

涉及文件：

- `src/pages/plaza/PlazaPage.tsx`
- `src/pages/plaza/PlazaPage.module.css`
- `src/pages/moments/MomentsPage.tsx`
- `src/pages/moments/MomentsPage.module.css`

广场建议采用“校园动态 + 发布按钮 + 筛选”的结构。帖子卡片统一头像、昵称、学校、时间、正文、图片和互动栏的顺序；图片使用固定比例缩略图，点击后进入详情，不在列表里强行展示过大的原图。

发布入口使用狐狸橙圆形按钮，发布面板内提供文字、图片、位置和可见范围。登录校验应在真正发布时触发，游客仍可浏览公开内容。发布失败要保留草稿文字和已选图片，避免用户重新填写。

广场空状态使用小狐狸和一句明确说明；加载失败使用重试按钮；审核中的内容显示给本人但不进入公开流。举报、删除和管理员审核保持原有权限逻辑。

### 5. 消息、聊天和联系人

涉及文件：

- `src/pages/MessagesPage.tsx`
- `src/pages/ChatListPage.tsx`
- `src/pages/ChatPage.tsx`
- `src/pages/ChatRoomPage.tsx`
- `src/pages/ContactsPage.tsx`

消息页优先展示未读数量和最近会话。系统通知、课程提醒、互动消息使用不同的小图标和浅色标记，不用大面积颜色区分整个列表。

聊天页保持大面积留白和稳定输入区：消息气泡使用暖象牙白与浅绿两种底色，自己的消息靠右使用森林绿；输入框、图片、表情和发送按钮固定在安全区域内。键盘弹出时不能遮挡发送按钮。

联系人、好友申请和私聊入口统一使用头像、姓名、学校/备注、最后状态四列信息，点击整行进入详情，右侧只保留一个动作。

### 6. 待办、任务和提醒

涉及文件：

- `src/pages/TodoPage.tsx`
- `src/pages/todo.module.css`
- `src/pages/TasksPage.tsx`
- `src/pages/TaskDetailPage.tsx`

待办页沿用首页“今日任务”卡片，但完整页增加日期分组和完成筛选。未完成事项使用森林绿勾选框，已完成事项降低文字对比度但保留清晰可读性。新建待办使用底部面板，标题、时间、提醒方式和重复规则分步填写。

提醒卡片要明确显示“通知、铃声、震动”开关和系统权限状态。用户关闭某种效果后，预览提示必须与实际设置一致。课程提醒和普通待办提醒分别显示，避免用户误以为待办设置会覆盖课表设置。

### 7. 个人中心与设置

涉及文件：

- `src/pages/ProfilePage.tsx`
- `src/pages/profile.module.css`
- `src/pages/SettingsPage.tsx`
- `src/pages/settings.module.css`

个人中心采用首页狐狸头像和身份卡，但信息分组要更克制：账号信息、学校与课表、提醒权限、应用设置、关于与更新。危险操作放在页面底部，并使用红色文字而非红色大按钮。

设置页将通知、定位、相册、精确闹钟和电池优化整理成“权限状态卡”。每项显示当前状态、用途说明和去设置按钮；已允许的权限不再反复弹窗。版本号、热更新和安装包更新放在独立的“关于哦狐”区域。

### 8. 管理端

涉及文件：

- `src/main-admin.tsx`
- `src/pages/AdminContentPage.tsx`
- `src/pages/AdminMembersPage.tsx`
- `src/pages/AdminNotifyPage.tsx`
- `src/pages/AdminCampusMapPane.tsx`
- `src/pages/AdminReportsPage.tsx`

管理端可以复用颜色和卡片语言，但不直接照搬学生端底部导航。桌面端使用左侧分组导航和右侧工作区，手机管理端使用顶部标题、分段筛选和底部操作条。

管理端首页优先展示待审核数量、待处理举报、提醒发送状态和地图新增地点。表格在窄屏下改为信息卡，详情和审核动作使用底部面板。审核通过、驳回、删除等高风险操作需要二次确认，并显示影响范围。

## 推荐实施顺序

1. 课表页和提醒设置：这是使用频率最高、错误成本最高的页面。
2. 服务页和学习工具：直接复用首页图标、卡片和状态组件。
3. 地图详情、地点提交和管理员审核：完成地图闭环。
4. 广场、朋友圈和发布流程：统一图片、空状态、审核和权限反馈。
5. 消息、聊天、联系人：重点处理输入区和未读状态。
6. 个人中心、设置和管理端：最后统一权限、更新和后台工作流。

每完成一个页面，都执行一次“真实数据/未登录/空数据/失败/窄屏/深色”验收，并保留截图。不要一次性批量重写所有页面；优先改完一个页面，再用实际截图校正间距、字体、图标边缘和操作反馈。

## 建议新增的复用组件

- `BrandCard`：统一卡片底色、圆角、内边距和暗色模式。
- `SectionHeading`：标题、原稿小图标、右侧更多入口。
- `StatusCard`：加载、空数据、失败和权限未开状态。
- `PermissionRow`：权限名称、用途、状态和系统设置入口。
- `BottomActionSheet`：登录、发布、地点提交和提醒设置共用。
- `OhuArtwork`：统一狐狸、标题图标和服务图标的裁切显示。
- `FilterPills`：地图分类、广场筛选、任务状态和服务分组共用。

## 当前限制与验收边界

原始图片没有提供可编辑图层和字体文件，因此后续仍以视觉比例、颜色、层级和交互一致为目标，不承诺像素级复制。真实课程、动态、地图地点和消息数量会随账号变化，验收时应优先检查数据状态和权限反馈，而不是固定文案。

本建议不要求更换 React、Vite、TypeScript、Capacitor 或现有数据层，也不要求新增假数据接口。后续实现前应先查看对应页面现有代码和测试，再逐页修改并运行 `npm run build` 与相关业务回归。
