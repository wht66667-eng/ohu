## 一、产品与运行形态

| 形态 | 说明 |
|---|---|
| 学生端 APK | `com.sunshinecampus.app`，Android（Capacitor 壳），arm64，支持 OTA 热更新 |
| 管理端 APK | `com.sunshinecampus.admin`，同一套代码、`admin` 壳，入口是管理工作台 |
| 官网 / H5 | CloudBase 静态托管，含下载页、产品介绍、公开 Meet 页 |
| 技术栈 | React 19 + Vite 8 + Capacitor 7；CloudBase 云函数；Capgo/自建 OTA |

**身份模型（与 UI 强相关）**

- 不需要手机号注册：**学号 = 本机身份**（`local-identity`），数据按 `uid: local:zhd-<学号>` 分区存在本机 localStorage。
- 密码默认不保存；勾选「记住密码」后用本机随机密钥 `sealSecret` 加密落盘，可按账号清除。
- 游客也能浏览部分页面；发布/私信/点赞等按需唤起登录面板（`ensureSignedIn`）。

## 二、信息架构

### 2.1 全局壳（App 内）

```
BootGate（首次免责声明 + 通知/权限引导，只出现一次）
```

## 三、核心用户流程

### 3.1 首次启动

1. `BootGate`：先看免责与边界说明，再完成通知/精确闹钟等权限引导（可跳过，之后在设置里补）。
2. 进入 `CampusGate` 门禁页（标题「首次认证」，见截图 `ohu-04-oneclick.png` 的同类版式）：
   - 学号（学号即本机身份，输入即写入 `local-identity`）
   - 校园网 / VPN 密码（2023 级默认身份证后 8 位；2024 级起后 8 位 + `@Jou`）
   - 统一认证密码（初始 `Jou@` + 身份证后 8 位）
   - 「记住密码」勾选（默认关闭）
   - 主按钮：**认证并进入**
3. 认证成功 → 写入 `ohu.campus-gate.v1`（本机已验证），进入 App，并在后台启动**教务同步**（成绩/课表/考试 → 公选 → 档案 → 学习通），逐项失败互不影响。
4. **本轮改造点**：门禁不再要求体测密码、也不再显示体测/PU 面板；体测与 PU 各自到成绩中心的子页「连接」。
5. 认证成功时把学号/校园网密码留在**本次运行内存**（`campus-session`），体测页可直接复用，不落盘；冷启动后由体测页自己再收一次。
6. 页面级同步（体测/PU）开始前会等后台同步跑完（`waitForBackgroundSync`，最多 90s），避免两个流程抢同一个内置 WebView。

### 3.2 入口门禁（当前设计）

```
填写三样 → ensureLocalIdentity → verifyCampusIdentity（VPN→CAS→正方）
   ├─ 成功 → rememberCampusSession → markCampusVerified → 进入 PhoneShell
   │           └─ 后台串行同步：教务 → 公选 → 档案 → 学习通（体测/PU 不在这里）
   └─ 失败 → 分阶段提示（校园网登录 / 统一认证 / 正方），不写任何数据
```

**流程特征**

- 门禁只做身份认证，进入 App 立刻显示首页；数据由后台同步补齐，首页在没有课表时显示「课表还没读取」状态条。
- 体测/PU 不在门禁或后台同步里被触发；页面级同步会先等后台同步结束，避免抢同一个内置 WebView。
- 同步入口分散在成绩中心与一键获取，失败只影响本项，旧缓存保留。

### 3.3 一键获取 / 更新数据（`/study/oneclick`）

1. 页面头部：设备内登录、不经过云端；四个信任标签（无需手机号 / 密码不写日志 / 默认不保存 / 只取本人数据）。
2. 「第 1 步 学号与密码」卡：
   - 学号、VPN、统一认证、记住密码
   - 主按钮 **更新数据**：一次跑 教务（成绩/课表/考试）→ 公选 → 校园档案 → 学习通
   - 次按钮 **只获取课表 · 成绩 · 考试**
3. 「第 2 步 需要单独更新的数据」卡：
   - 学习通（授权并读取）
   - 公选选课（正方 xsxkqk）
   - 校园档案（实验）
   - 体测成绩 → **去体测页**
   - PU 二课 → **去 PU 页**
4. 下方：密码规则说明、清除本机保存密码、安全与边界文案。
5. 状态反馈：阶段条（`校园网登录 · 正在…`）、来源结果 chips（成功/失败/条数）、notice/error 两行文案。

### 3.4 体测成绩：独立账号「连接」+ 底部弹层（本轮改造）

入口：成绩中心 → 体测成绩（`/grades?tab=tice`；旧 `/sports/results` 自动跳转，截图 `ohu-02-tice.png` 为改造前的等价版式）

```
最近一次体测（大分数 + 等级 + 最好成绩）
体测系统状态卡
   ├─ 未连接：说明 + 「连接体测系统」
   ├─ 已连接：「已连接」+ 「更新体测成绩」+「修改或断开」
   ├─ 运行中：「正在登录…」+ 阶段文案 + 取消（关闭内置 WebView）
   └─ 完成：成功条数 / 失败原因（不覆盖旧数据）
连接弹层（ActionSheet）
   ├─ 学号 / 校园网密码 / 体测密码
   ├─ 「保持连接（本机加密保存，下次免输入）」
   ├─ 主按钮「登录并读取成绩」；已连接时多一个「断开连接」
   └─ 进行中在同一弹层显示阶段与错误
粘贴导入 / 手动录入（保留）
本次 / 历年 / 标准（趋势图 + 记录卡 + 项权重）
```

**凭据来源优先级**：已保存的一键获取凭据 → 本次运行的门禁会话 → 用户当场输入。  
**连接策略**：默认「保持连接」，成功后加密保存；「断开连接」清掉体测密码但保留学号/校园网凭据。

### 3.5 PU 成绩：独立账号「连接」+ 底部弹层（本轮改造）

入口：成绩中心 → PU 成绩（`/grades?tab=pu`；旧 `/study/pu` 自动跳转）

```
校园档案 7058 卡（A/B/劳动 参考进度）
Hero：总学分 / 活动类 / 成果类 / 更新时间
   └─ 「更新 PU 学分」：复用已连接账号或口袋校园登录态
口袋校园状态卡
   ├─ 未连接：「连接口袋校园」→ 弹层
   ├─ 已连接：「更新 PU 学分」+「修改或断开」
   ├─ 运行中：阶段文案 + 取消
   └─ 完成：总学分 + 明细条数；失败保留旧缓存
连接弹层（ActionSheet）
   ├─ PU 账号 / PU 密码
   ├─ 「保持连接（本机加密保存）」
   └─ 主按钮「登录并读取学分」；已连接时多一个「断开连接」
已保存概览 / 导入卡 / 口径说明（保留）
```

**两种登录方式**：填写账号密码后台自动登录；或打开口袋校园页面手动登录一次，之后复用登录态。自动登录失败会明确提示「只尝试了 1 次」，避免锁号。

### 3.6 成绩中心：一页四子页（本轮改造）

- `/grades`：顶部四子页 **课程成绩 / 公选进度 / 体测成绩 / PU 成绩**，共用一个「更新于 … · 同步失败保留旧数据」状态条。
  - 课程成绩：平均分/总学分/课程数 + 搜索 + 学期筛选 + 课程表。
  - 公选进度：H/R/Z/G 分类、每类 2 学分上限、已修列表与目录。
  - 体测成绩：最近一次 + 独立账号连接 + 粘贴/手动录入 + 本次/历年/标准。
  - PU 成绩：7058 参考进度 + 官方学分连接 + 明细 + 导入兜底。
- 旧入口 `/grades/courses`、`/grades/public`、`/sports/results`、`/study/pu` 都会重定向到对应子页，侧边栏、首页、外部深链不用改。
- `/study`：学业中心 Tab（首页 / 成绩 / 考试 / 证书 / 端口），负责考试与学习工具；`/study/quality`（素质拓展 7058）、`/study/chaoxing`（学习通）保持独立页。

### 3.7 首页：时间敏感优先（本轮改造）

首屏顺序：**问候 → 下节课 → 最近考试 → 最近课程 → 待办**；没有课表时顶部出现「课表、成绩、考试还没读取 · 去读取」状态条。  
原来的「学业中心」大卡已移除（成绩中心在导航与快捷功能里都能到），首屏卡片数减少，考试倒计时更靠前。

### 3.7 课表 / 今日安排 / 提醒

- `/schedule`：周视图 + 今日高亮；支持图片/教务同步、单双周、调课。
- 首页「下节课 / 最近课程 / 考试倒计时」都读本机课表缓存。
- 提醒：`RemindHost` 统一排程（课程、考试、待办、常驻），设置里可调提醒时间与弹窗样式，支持自检通知。

### 3.8 社区与社交

- 广场 `/plaza`：信息流 + 大厅（lobby）+ 分类；发布用中央「＋」。
- 动态 `/moments`、私信 `/chats`、联系人 `/contacts`、消息 `/messages`。
- 游客可浏览；互动时按需唤起登录/学号身份。

### 3.10 更新与下载

- APK 更新：官网下载页（`/download/student.html`）给出最新包、SHA-256、大小；管理端同理。
- 设置 → 关于里展示「界面版本 / 安装包版本」两个号，避免热更误判。

## 五、UI 模式与设计语言

- **卡片式布局**：`--card` 底 + `--line` 描边 + 18–24px 圆角；区块标题用 kicker（小号绿色）＋ h2/h3。
- **主色**：绿色系（`--green` / `--green-soft` / `--green-text`），危险态用 `--danger-soft`。
- **按钮层级**：`primary`（实心绿，主操作）→ `outline`（描边，次操作）→ `ghost`（文字类，危险/低频）。
- **弹层（ActionSheet）**：体测/PU 的账号连接统一用底部弹层；连接成功后页面只留一行「已连接 · 更新 / 修改或断开」。
- **反馈**：阶段条（进行中）、`success`（绿底条）、`error`（红底条）、Toast；不弹阻塞式对话框处理同步。
- **空态**：说明 + 下一步动作（去一键获取 / 去课表 / 登录）。
- **可访问性**：skip link、aria-label、focus-visible 描边、`prefers-reduced-motion` 降级。
- **字体与密度**：正文 13–15px，辅助 11–12px；移动端单列，宽屏自适应两列。

## 六、数据与隐私边界（影响文案与交互）

- 密码只在设备内使用；不发给哦狐服务器、不写日志、错误提示不回显密码。
- 默认不保存；保存时按账号加密；设置里可一键清除。
- 「学号即身份」：换设备要重新同步；登录/退出不删除课表/成绩/体测本机数据（显式清空才删）。
- 每个数据源独立缓存键，失败保留旧缓存；页面上明确写「更新于 … / 非实时数据」。
- 体测/PU 的登录是**独立授权**，与入口门禁解耦；解除 PU 授权只清 PU 会话，不动校园网会话。

## 七、观察到的体验问题与优化建议（供排期）

> **本轮已实现**：① 门禁后自动后台同步教务（首页有未同步状态条）；② 体测/PU 改为「连接/已连接/断开 + 底部弹层」；③ 成绩/公选/体测/PU 合成一个成绩中心四子页（旧路由重定向）；④ 首页改成「下节课 → 最近考试 → 最近课程 → 待办」；⑤ 体测/PU 同步前等待后台同步，避免抢 WebView。
> 下面保留原始观察，作为后续排期参考。

### 高优先级

1. ~~**门禁后首屏可能没有数据**~~：已改为门禁后后台同步教务；如果同步失败或还没跑完，首页显示「课表、成绩、考试还没读取」状态条。
2. **体测/PU 的密码心智成本**：体测密码规则（姓名首字母_学号）容易被忘。建议在连接弹层里内置「按学号生成初始密码」按钮（需姓名首字母），并在失败时给出「去体测系统找回」的链接。
3. **PU 登录的风控风险**：自动填表连续失败可能锁号。建议失败一次就停、明确提示「只尝试了 1 次」，并优先引导「打开页面手动登录」。（本轮已把失败文案改为单次尝试提示，仍可再加锁号保护）
4. **同步入口分散**：成绩中心已有统一状态条；下一步把「全部更新 / 单源更新」做成一个数据状态面板（设置与首页复用）。

### 中优先级

5. **门禁认证耗时**：VPN→CAS→正方三步串行，缺少进度分解的可感知反馈（当前只有一条阶段文案）。建议显示三步进度/预计等待。
6. **体测页信息层级**：最近成绩 hero、登录卡、粘贴导入、手动录入、历史/趋势都在一屏，首次使用容易迷路。建议默认只展示 hero + 登录/更新，导入类折叠到「更多方式」。
7. **PU 页口径卡片与官方卡片并列**：7058 与口袋校园两套口径容易混。建议在页面顶部固定一条「两套口径不混算」的说明条，或把 7058 收进折叠区。
8. **错误文案偏技术**：如「体测页面没有解析到成绩（debug 信息）」。建议对用户展示可行动的下一步，debug 信息折叠。
9. **空态引导重复**：首页、体测、PU 都写「去一键获取」。既然已分页登录，文案应改成对应页面的「登录并更新」。
10. **更新提示的版本号**：界面版本/安装包版本两套号，普通用户不理解。建议在更新卡里只强调「新功能」，版本号放小字。

### 低优先级 / 打磨

11. 体测页「标准」tab 指向国家标准的说明偏学术，可加一句「学校评分标准未接入」的原因链接。
12. PU 明细行信息密度高，可加分类筛选或折叠。
13. 首页问候语只显示学号后 4 位（`xxxx 同学`），可结合院系/年级做更自然的称呼。
14. 设置里「更新数据」与「数据与缓存」两个分区的职责边界可以在文案上再拉开。
