# QuickJump 快递入口接入说明

初次接入日期：2026-10-20，对应本地版本 1.2.128／128，当时未上传或提交热更新。该功能现已随 2026-10-21 的 1.2.129 APK 与热更新发布，当前发布结果见《1.2.129发布验收.md》。以下保留初次接入的实现与检查记录。

## 功能与使用位置

在“服务 → 快递查询”打开“取件与查物流”；快递代取任务详情中的“查快递物流”也使用同一个窗口。游客可浏览服务，使用快递工具时先进入哦狐登录。

| 分组 | 快捷入口 |
| --- | --- |
| 取件身份码 | 菜鸟身份码、淘宝身份码、拼多多身份码 |
| 待取与订单 | 淘宝待取快递、拼多多待取快递、抖音订单、京东订单 |

原来的按单号识别和查物流保留在“按单号查物流”折叠区；修正了失败回退可能重复打开网页的问题。窗口使用项目已有的弹窗组件，支持返回、Escape 和焦点恢复。

## 接入的是哪一种能力

用户截图对应 [chuhe0719/QuickJump](https://github.com/chuhe0719/QuickJump)，核对源码版本为 `df94cd7ab1cbca5171139259f63b44dc61cf8e9c`。

该项目提供页面跳转入口，没有可供哦狐调用的身份码聚合 API。它不返回账号、身份码或待取件数据，也没有自己绘制条码和每十分钟刷新的任务。身份码显示、放大、有效期与刷新均由对应平台页面负责。

本次参考其公开入口地址，在哦狐现有 React／Capacitor 项目中独立实现界面与 Android 跳转桥；不需要另外安装 QuickJump。

原仓库 README 写六入口，当前源码实际包含京东在内的七入口。抖音和京东链接打开的是订单入口，因此哦狐使用“订单”文案，不承诺已过滤为待取件。

## 各端行为

- 安卓新版 APK：优先向固定平台 App 发起页面跳转，失败后依次尝试备用地址、App 首页和已有的平台网页。抖音兼容正式版与极速版，没有编造网页回退。
- 安卓旧 APK：缺少新增接口时明确提示需要新版 APK；有平台网页的入口提供手动替代链接。
- 电脑、普通手机浏览器和 iOS：使用平台网页；抖音入口明确显示仅安卓 App 支持。部分取件网页仍要求手机 App 或平台登录，不能保证桌面浏览器显示身份码。

Android 返回成功只代表系统接收了打开请求，不能证明第三方 App 已完成登录或进入指定页面。若落到平台首页，需要在该 App 内继续查看。

## 原生实现与数据边界

- 新接口为 `AppProbe.openExpressEntry({ entryId })`，只接受七个固定入口标识。
- 包名与候选地址由原生代码固定登记，不接收调用方传入的任意 URL、组件或 Intent 参数。
- 返回 `direct`、`app`、`web` 或 `unavailable`，第一条成功后即停止，不继续覆盖已打开的页面。
- 只补充六个目标包的可见性声明，不新增短信、通知、相册、定位或后台权限，不清空第三方 App 现有任务。
- 不读取或保存平台登录凭据、身份码、订单和待取包裹，不新增云端接口。

原仓库未附独立 LICENSE 文件，README 声明个人学习自用、不要上架应用商店。本次未复制其 Kotlin 界面或图标资源；公开地址配置的来源保留在代码和本说明中。

## 安装包与后续验收

新增原生接口需要新版 APK，单独热更新无法给旧安装包补齐。此次只准备本地安装包，不自动安装手机，不上传 APK，不更改线上版本清单，不提交热更新。

两端本地安装包已生成，均已核对原签名、包名、版本与 arm64 架构，并检查 APK 内确实包含新跳转接口、七入口及对应端的网页资源：

- 学生端：`.release-out/apk/1.2.128-128/SunshineCampus-User-1.2.128.apk`
- 管理端：`.release-out/apk/1.2.128-128/SunshineCampus-Admin-1.2.128.apk`
- 签名、包名、版本和文件校验信息：同目录 `release-both.json`。
- 此次接入交付记录：`.release-out/express-quick-jump-128.json`。

装机后逐项验证：

1. 安装新版哦狐，登录本人哦狐账号。
2. 已安装并登录对应平台 App 后，逐一测试七个入口。
3. 核对身份码由正确平台显示，能正常出示；抖音／京东订单可继续查物流。
4. 测试平台未安装、入口失效、抖音极速版等回退情况。
5. 核对原单号查询与应用其他功能正常。
