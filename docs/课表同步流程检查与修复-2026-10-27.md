# 课表同步流程检查与修复（2026-10-27）

## 本轮范围

检查“教务登录 → 同步课表/成绩/考试 → 保存本机快照 → 更新课程提醒”的学生端真实流程，不使用模拟成功数据。

## 已确认并修复的问题

教务成功返回 `rows: []` 时，旧实现只清空当前画面，或直接跳过课表保存。旧课程快照和旧课程提醒可能继续存在，重新打开页面后旧课程还会出现。

本轮改为：

- 自动同步、课表验证码同步、学业中心同步都保存成功的空课表结果；
- 空课表快照带 `confirmedEmpty: true`，与损坏或旧版遗留的空记录区分；
- 已确认空课表仍保留当前 App 账号和学号绑定，避免每次冷启动重复登录教务；
- 空课表保存后调用课程提醒重排，清除该账号的旧课程通知和桌面提醒；
- 页面明确显示“课表 0 条（已清除旧课程与提醒）”，不把空课表伪装成同步失败；
- 成绩和考试按各自结果独立保存，部分失败时保留原缓存。

## 账号与数据边界

- 快照仍按 App UID 隔离；
- 旧版无归属空记录不会被自动认领；
- A → B → A 切换期间返回的旧请求仍会被拒绝；
- 存储写入失败时不报告同步成功。

## 验证结果

- 学业同步、课表缓存、学校入口、节次设置、课程提醒及安卓通知策略：90 项通过，0 失败；
- `npm run build`：通过；
- 未连接真机，本轮没有宣称真实教务账号登录或安卓后台送达已经完成真机验收。

## 下一步真机验收

1. 用真实教务账号同步有课课表，确认课程、成绩和考试数量；
2. 修改课程后再次同步，确认旧提醒被替换；
3. 在教务返回空课表的测试条件下，确认旧课程和旧提醒不再出现；
4. 划掉最近任务后，验证课前 15 分钟和开课时两次提醒；
5. 验证超过预定时间 1 分钟的课程提醒直接作废。
