# 体测与 PU（口袋校园）获取方式

> 2026-11-07 · 对应学生端「一键获取」里的「体测 + PU」面板
> 目标：用户只在一个窗口填一次账号，App 在后台完成登录、跳转、读取，不再弹出登录页。

---

## 一、体测（tice.jou.edu.cn）

### 1. 系统与入口

| 项目 | 值 |
|---|---|
| 学校系统 | `tice.jou.edu.cn:8080`（体测系统） |
| 校外访问 | WebVPN 网关 `/http-8080/<tice-hex>/` |
| 网关地址 | `http://webvpn.jou.edu.cn:58888` |
| 应用 hex | `77726476706e69737468656265737421e4fe4299693a6745300d8db9d6562d` |
| 账号 | 学号（与教务相同） |
| 密码 | 体测系统独立密码；首次一般是「姓名首字母大写_学号」，例如 `AAA_2023111111` |

### 2. 获取方向

体测走**直接 HTTP 表单**，不依赖页面按钮：

```
WebVPN 登录（复用主流程的 VPN 会话）
        │
        ▼
POST /http-8080/<hex>/studentFrame.jsp
     operType=911
     loginflag=0
     loginType=1
     userName=<学号>
     passwd=<体测密码>
        │  服务端 Set-Cookie，建立体测会话
        ▼
GET  /http-8080/<hex>/Historyhealth.jsp        ← 历年成绩
GET  /http-8080/<hex>/queryHealthInfo.jsp      ← 本次 / 单项明细
（失败时回退 /left1.jsp?userName=&passwd=）
        │
        ▼
tice-parse.ts 解析表格
        │
        ▼
physical-test-results.ts → importTiceSummary()
        │
        ▼
本机缓存（按学号隔离），「体测成绩」页展示
```

### 3. 解析与保存

- 解析器：`src/lib/tice-parse.ts`
- 结果模型：`src/lib/physical-test-results.ts`
  - `totalScore: number | null`
  - 学年、测试日期、等级、单项明细
- 保存：只保存学年/日期/总分/最多 12 项明细；不保存姓名、学号、cookie、原始 HTML。

### 4. 当前实测

真机已跑通：

```
体测：成功 · 3 条
2025-2026  70 分
2024-2025   0 分
2023-2024  44 分
```

### 5. 失败点与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 登录后仍是登录页 | 密码错误或账号不是学号 | 提示「体测密码不对，首次可试 姓名首字母_学号」 |
| 页面能进但没有表格 | 学校页面改版 / 学期无数据 | 回退 `left1.jsp`，再走页面文字导入 |
| 需要验证码 | 体测系统偶发验证码 | 转可见页面手动完成一次 |

## 二、PU（口袋校园）

### 1. 系统与入口

| 项目 | 值 |
|---|---|
| Web 端 | `https://class.pocketuni.net/` |
| API | `https://apis.pocketuni.net` |
| 登录接口（页面内部） | `POST /uc/user/login`（JSON，`withCredentials`） |
| 账号 | 口袋校园手机号 / 学号 |
| 密码 | 口袋校园密码（与学校密码无关） |

### 2. 获取方向（当前实现）

PU 的登录接口有加密/风控参数，直接调 API 需要逆向 `/uc/user/login` 的完整请求体；当前采用**后台 WebView 自动填表**，稳定且不弹窗：

```
用户在一个窗口输入：PU 账号 + PU 密码
        │
        ▼
后台 WebView（不显示）加载 https://class.pocketuni.net/
        │
        ▼
若出现「密码登录」tab → 点击
        │
        ▼
找到 input[type=password]，取同一表单里的第一个
text/tel/number 输入框作为账号框
        │
        ├─ 写入账号 → input/change 事件
        ├─ 写入密码 → input/change 事件
        └─ 点击「登录」按钮（找不到则 form.submit()）
        │
        ▼
等待登录成功：
  · 页面出现「我的成绩 / 成绩明细 / 总成绩」
  · 或：密码框消失 + URL 离开 /login + 页面有内容
        │
        ▼
跳到成绩明细（#/score/detail）
找不到就点击文字「成绩明细」
        │
        ▼
读取 document.body.innerText
        │
        ▼
pocketuni-parse.ts → parsePuPageText()
  识别：【类别】项目名称（学分）
        │
        ▼
pocketuni-store.ts → savePocketUni()
        │
        ▼
本机缓存，「PU 二课」页展示
```

### 3. 解析规则

- 解析器：`src/lib/pocketuni-parse.ts`
- 典型文本：

```
活动类 4.25 + 成果类 0.60 = 总成绩 4.85
【素质拓展B类】团员主题教育（0.85）
【劳动教育】公益劳动（1.00）
```

- 只取「【类别】名称（学分）」行，按类别汇总；总成绩单独识别，不把 PU 学分和公选学分相加。

### 4. 当前状态

- 「体测 + PU」面板已上线：一个窗口三个输入（体测密码、PU 账号、PU 密码）。
- 体测已实测通过。
- PU 自动填表逻辑已完成；**还差一次真实账号验证**（需要用户输入自己的 PU 账号密码，避免误锁）。
- 若自动登录失败，回退方案：点「授权并读取」打开可见页面手动登录一次，之后复用 cookie。

### 5. 失败点与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 找不到密码框 | 页面改版 / 默认是验证码登录 | 先点「密码登录」；仍失败则回退可见登录 |
| 填了账号但提示账号不存在 | 账号类型不对（手机号/学号） | 提示用户换另一种账号形式 |
| 登录后停在首页 | 成功判定过早 | 已改为「密码框消失 + 离开 /login」判定 |
| 成绩页是 canvas | 学校用图片渲染成绩单 | 回退页面文字导入 / 截图识别 |
| 账号锁定 | 连续输错（服务端 maxFailTimes=2） | 只尝试一次，失败即停，提示手动登录 |

## 三、两条链路的区别

| | 体测 | PU |
|---|---|---|
| 登录方式 | 直接 POST 表单 | 后台 WebView 自动填表 |
| 是否需要页面 | 不需要 | 需要 SPA 渲染 |
| 密码来源 | 体测独立密码 | 口袋校园独立密码 |
| 数据页面 | `Historyhealth.jsp` / `queryHealthInfo.jsp` | `#/score/detail` 文本 |
| 解析 | HTML 表格 | 页面文字（【类别】名称（学分）） |
| 当前验证 | ✅ 真机通过 | ⏳ 等真实账号验证 |
