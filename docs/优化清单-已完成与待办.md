## 〇之三、图片完全无法上传（1.2.107 已修并已发 OTA）

### 现象
管理端发公告选不了图，学生端广场发不了图；**点了图片就转圈，然后没动静**。头像偶尔能成。

### 根因：不是上传代码写错，是「登录态被静默降级成游客」

查了一遍发现上传代码完全没问题，真正的链条是：

1. **CloudBase SDK 的 auth 默认 `persistenceTag='session'`** —— 会话写进 sessionStorage；
2. **Capacitor WebView 冷启动后 sessionStorage 被清**，会话读不回来；
3. `auth.tsx` 的 bootstrap 发现「无会话」，**静默** `signInAnonymously()` 降级成游客
   （`src/lib/auth.tsx:379` 的 `else if (!cur)` 分支）——界面一切照常、功能都在，
   用户完全不知道自己已经是游客；
4. images 桶所在 `storage.objects` 表的 INSERT 策略 `authenticated_upload`，其 `with_check` 是：

   ```sql
   ((auth.role() = 'authenticated') AND (bucket_id = 'images'))
   ```

   **匿名用户的 `auth.role()` 不是 `authenticated`，写入被行级安全直接拒绝。**

### 实测证据（写探针跑出来的）

| 会话形态 | 结果 |
| --- | --- |
| 无会话 | `401 MISSING_CREDENTIALS` |
| 匿名会话（signInAnonymously） | `403 STORAGE_ACCESS_DENIED` —— `PG RLS error: new row violates row-level security policy for table "objects"` |
| 正式会话 | 200 成功 |

**关键：与目录无关。** `avatars/` 在匿名态同样 403 —— 所以不存在「某个目录没权限」这种解释。

桶内对象分布也印证这条链：只有 `avatars/` 有历史成功记录，`chats/` `plaza/` `news/` `ugc/` 一条都没有。

**为什么管理端更糟**：管理端（admin 壳）**没有任何自动重登机制**（学生端尚有「学号+教务密码」
兜底，见 `auth.tsx:350` 的 `hasCampusGatePass()`），所以 session 一丢就永远发不了图。

### 修复（三处）

| 文件 | 改动 |
| --- | --- |
| `src/lib/cb.ts` | `cloudbase.init` 与 `cbAuth()` **均显式指定 `persistence: 'local'`** —— 会话改存 localStorage，跨冷启动保留（**治本**，一次登录长期有效） |
| `src/lib/upload-error.ts` | 新增零依赖的 `uploadGuardError(getCurrentUser)`（用传 getter 的方式保持本模块零依赖，不破坏 `tools/*.test.mjs` 的 mock 白名单） |
| `src/lib/chat-image.ts` / `market.ts` / `account.ts` | 三条上传链路在**发请求前**先判游客态，命中直接提示「当前是游客状态，不能发图。请退出后重新登录再试」，不再让用户对着「请稍后重试」干等 |
| `tools/task-images.test.mjs` | mock 补 `uploadGuardError`（返回 null＝不阻断，与线上降级策略一致） |

### 验证
`tsc -b` 0 错、`oxlint src/ tools/` 0 error、单测 **335/336**（唯一失败仍是环境固有的 javac EBUSY）。
产物内已确认：`cb-*.js` 里两处 `persistence:\`local\``（init 配置 + `auth({persistence:'local'})`），
守卫文案与调用也都在包里。

⚠️ **注意：vite 会把字符串压成反引号（`` `local` ``），grep 时别用 `"local"` 去匹配，会误以为没进包。**

### OTA 1.2.107 双壳已发布
user checksum `e561de43…d8e7` / 2,779,341 B；admin `6afece8f…4839` / 2,779,296 B。
本地 zip SHA256 与线上 manifest 逐字一致，HTTP content-length 三方吻合，bundle 200 + `application/zip`，
老路径 `/ota/manifest.json` 已同步。**壳仍是 1.2.106**（纯 Web 改动，gradle / capacitor 内置包标签不动）。

### 7c. 上传功能排查（你报「上传图片都不能用」）✅ 已定位

不是代码 bug，是**权限 + 文案**问题。三个证据：

1. **SDK 调用形态是对的**：实测 `app.storage` 存在，`upload(path,file)` / `getPublicUrl()` 签名无误；桶 `images` 存在、`Public=true`、10MB 上限。
2. **登录态链路是通的**：桶里 28 个对象按目录看，`avatars/` 有 **10-10 当天上传成功的 4 条记录**；但 `chats/` `plaza/` `news/` `ugc/` **一条都没有**。
3. **匿名（游客）上传必然 403**：实测 `signInAnonymously()` 后上传返回 **403 STORAGE_ACCESS_DENIED**。桶的 RLS 只有 `authenticated_upload`（INSERT 限 `authenticated` 角色），而项目在「无会话」时会静默匿名登录当游客。

**根因**：所有失败都被压成一句「图片上传失败，请稍后重试」，掩盖了「没权限/没登录」这个真实原因。

**修复**：新增零依赖的 `lib/upload-error.ts`，把 403 / 401 / 413 分别翻成人话，并把原始错误 `console.warn` 出来。

| 状态码 | 新文案 |
| --- | --- |
| 403 `STORAGE_ACCESS_DENIED` | 没有上传权限：请先登录（游客不能发图） |
| 401 | 登录状态已失效，请重新登录后再试 |
| 413 | 图片太大了，请压缩到 2MB 以内 |

> **为什么单独放 `upload-error.ts` 而不是塞进 `chat-image.ts`**：`market.ts` 若从 `chat-image` 拿这个函数，会间接引入 `./cb`，破坏 `tools/task-images.test.mjs` 的模块隔离（实测会让用例挂掉）。零依赖模块最安全。

**还需要你确认的**：如果你是在**已登录**状态下发的图仍失败，那上面的结论不够——请把 toast 文案（现在会显示具体原因）或 logcat 里的 `[上传失败]` 那行发我。
