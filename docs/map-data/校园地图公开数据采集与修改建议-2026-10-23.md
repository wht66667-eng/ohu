## 地图底图与瓦片建议

底图样式、底图瓦片和校园 POI 是三种不同数据：样式 JSON 定义颜色、字体与图层；瓦片提供道路、建筑、水系等底层几何；项目 `campus_pois` 则用于显示校内重点地点。当前 `map_style_url` 为空，所以即使导入候选校区和 POI，页面仍会显示未配置底图。

推荐做法是选一个条款允许应用商用/公开访问且支持 MapLibre 的 OSM 派生服务，或者用有明确授权的 OSM 区域提取数据自行生成并托管矢量瓦片与样式。不要批量抓取 `tile.openstreetmap.org` 的 PNG 瓦片制作 MBTiles；OSMF 的瓦片政策明确禁止批量下载和瓦片归档。若使用 OSM 数据/底图，应在地图可见位置展示 OpenStreetMap 署名，并提供 ODbL 许可链接。PMTiles 可由 MapLibre 直接读取、托管在支持 HTTP Range 的对象存储上，适合作为自托管矢量数据格式。

## 对现有项目的修改建议

1. 在管理端增加“导入候选数据”功能：只接受 GeoJSON，导入前展示校区中心/POI 数量、来源和人工检查状态；默认全部禁用，管理员勾选验收后才写 `campus_campuses`、`campus_pois`。
2. 数据库补充来源元数据（如 `source_url`、`source_license`、`verified_at`、`coordinate_system`），避免以后无法追溯坐标和授权；当前 `campus_pois` 表只有名称、类别和坐标。
3. 样式设置增加瓦片连通性、HTTPS、跨域和 MapLibre 样式 JSON 验证；空样式时显示各校的可用状态和待配置原因。
4. 为学校和校区分别保存默认视野缩放级别；中心点不应复用为校门 POI。
5. 底图若由自托管 OSM 提取生成，保存原始数据日期、提取范围、生成工具版本及 ODbL 署名信息，并配置 COS/CDN 的 Range 与 CORS。现有 README/交付材料提到的“少量 MBTiles”和 Martin 容器方案仍需实测瓦片格式、启动参数、CPU/内存、跨域和 CloudBase Run 挂载能力，不能仅凭示例配置视为部署完成。
6. 线上执行 `docs/sql/campus-map-132.sql` 之前先审查 RLS/权限，再由项目管理员实施迁移；本次未访问或修改线上数据库。
