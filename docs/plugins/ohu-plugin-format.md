# 哦狐内置插件格式（v1）

## 目标与发布方式

哦狐 v1 插件是轻量、单用途的 React/TypeScript 功能模块，由审核人员审查后静态注册，并随学生端 Web 构建和 APK 一起发布。用户在“服务 → 哦狐插件”或“我的 → 哦狐科技”启用或停用已发布的模块；非官方模块首次默认停用，显式选择按本机账号保存。

APK 不从 GitHub 下载或运行插件代码；不使用 `eval`、`new Function`、远程脚本、动态导入 URL、WebView 任意页面注入或插件自带的原生二进制。GitHub 目录中的项目只是参考链接，不是可安装模块。

## 目录约定

```text
src/plugins/
  plugin-manifest.ts       # 元数据、权限类型、用户偏好存储
  registry.ts              # 唯一的静态插件注册表
  builtin/
    FocusShortcut.tsx      # 内置插件实现
    ScheduleReminder.tsx   # 内置插件实现
docs/plugins/
  ohu-plugin-format.md     # 本规范
```

## 必填清单字段

```ts
interface OhuPluginManifest {
  id: string                 // 小写 kebab-case，发布后不可复用
  version: string            // SemVer
  name: string               // 面向学生的短名称
  author: string             // 展示的插件创作者
  category: '学习效率' | '校园生活' | '趣味探索'
  summary: string            // 说明单一、可理解的用途
  entryPath: string          // 只能指向哦狐内部已登记路由
  permissions: Permission[]  // 最小权限，不能省略或用通配权限
  bundled: true              // 必须由应用构建打包
  reviewed: true             // 仅审核通过后方可注册
  official: boolean          // 区分哦狐官方模块与非官方趣味内容
  sourceName?: string        // 外部灵感／代码来源（如适用）
  sourceHref?: string        // 精确 GitHub 仓库地址（如适用）
  sourceLicense?: string     // 展示许可和实际复用情况（如适用）
}
```

当前权限白名单：

| 权限 | 含义 | 不包含 |
|---|---|---|
| `schedule:open` | 打开哦狐课表视图 | 读取课表数据、教务密码、后台同步 |
| `todo:open` | 打开哦狐待办功能 | 批量创建或删除任务 |
| `focus:open` | 打开哦狐专注功能 | 在后台启动计时或控制其他应用 |
| `word-study:read` | 读取当前账号本机单词计划与复习卡 | 读取其他账号、云端凭据 |
| `word-study:write` | 保存当前账号本机复习进度 | 修改其他账号、上传个人数据 |
| `qbank:read` | 读取当前账号本机题库 | 云端查询、修改题目、提交答案 |

无权限的纯本地插件可使用空权限数组。含第三方灵感的独立实现仍应标注 `official: false`，并在商城展示来源及许可；这不代表哦狐或上游作者对占卜内容作背书。

新增权限类型需要先审查数据流、用户提示和拒绝权限后的行为，再通过代码评审扩展白名单。禁止静默索取通讯录、定位、相册、账号凭据或完整文件权限。

## 模块接口与静态注册

插件控件使用明确的 props 与哦狐内部路由；不要直接操作宿主全局对象或私有数据库。

```tsx
export function ExamplePlugin({ enabled, onToggle }: {
  enabled: boolean
  onToggle: () => void
}) {
  return <button type="button" aria-pressed={enabled} onClick={onToggle}>
    {enabled ? '已启用' : '启用插件'}
  </button>
}
```

新模块必须显式加入 `src/plugins/registry.ts`，清单 ID 必须唯一。插件通过仓库内显式导入进入 Vite 依赖图，因而会随当前 Web 版本及 APK 构建；只上传清单、二维码或 GitHub 地址不会把代码安装进用户的 APK。

## 插件作者：提交与接入

当前联系表仅用于提交方案和 GitHub 仓库链接，不支持直接上传 ZIP、APK 或源码附件。作者按下面步骤准备：

1. 建立可公开查看的 GitHub 仓库，包含源码、清单字段、README、适用许可证、依赖清单、功能截图和本地运行／构建说明。不要提交密钥、密码、教务账号、真实用户数据或签名文件。
2. 按本规范说明唯一插件 ID、版本、单一用途、哦狐内部入口、最小权限、数据处理、网络请求、第三方依赖和兼容范围，并写出自己执行过的检查。
3. 在哦狐“我的 → 哦狐科技”点“我是插件作者：如何提交？”查看流程，再点“提交插件接入方案”。联系表里粘贴仓库 URL 并补充功能、权限、许可证与测试信息。
4. 管理员先审核来源、代码安全、许可证、隐私、权限、稳定性和校园适用性。表单提交不表示审核通过或已安装。
5. 审核通过后，由哦狐维护者把源码纳入正式仓库、静态注册、构建并发布新版。维护者会确认许可声明与版权要求；外部作者不能自行将代码推送到学生安装包，也不能让 APK 运行远程脚本。

如暂时没有可审查的代码仓库，可以先提交功能建议和原型说明；它只进入评估，不会显示为可启用插件。审核结果由管理员通过哦狐现有反馈渠道回复。

## 用户：启用与使用

1. 打开“服务 → 哦狐插件”，查看哦狐内置模块的用途、创作者、版本和数据用途。
2. 点击“未使用 · 点击启用”，之后使用对应工具；点击“使用中 · 点击停用”可停用，操作组件会卸载并清空临时输入。停用课表快捷插件仅隐藏其入口，不取消已设置的课程提醒。
3. 插件只有在审核、静态注册并随哦狐新版本发布后，才会出现在“哦狐内置插件”区域。用户安装／更新哦狐版本后即可启用，不需要从第三方网站安装 APK。
4. GitHub 开源参考卡片只打开仓库页面，不会自动下载、安装或运行代码。
5. 当前星级只在本设备本账号保存，是个人使用备注；它不会上传、跨设备同步或形成公开总分。

## 交互与评分

- 每个插件只解决一个常见、容易理解的小问题；商城展示用途、版本、类别、权限和审核状态。
- 用户可启用／停用；关闭后商城仍保留入口，可再次开启。
- 当前 v1 星级只保存在本设备、按账号隔离，不作为公开平均分，不上传服务器，也不应宣传为社区评分。
- 全站评分、评论与举报需要另行设计云端数据表、RLS、反刷分与内容审核；完成前不显示虚构的评分人数或平均分。

## GitHub 开源项目接入审查

接入参考项目之前必须固定具体仓库与 commit，核对许可证全文、依赖、安装脚本、网络请求、遥测、存储、权限和供应链风险。按适用许可证保留版权／声明，记录来源、修改内容和版本。AGPL 等可能带来额外源代码提供义务的许可证，应由项目负责人确认兼容方式；未确认前只展示外链，不复制或打包其代码。

所有第三方或用户提交模块先由管理员审核源码与权限，再进入静态注册表、构建和发布流程。插件作者不能上传 JS 后让生产 App 自动执行。自动刷课、代答、伪造平台学习记录、绕过校园平台访问控制的插件拒绝接入。

## v1 验收标准

1. 插件 ID 唯一；清单只声明白名单权限与哦狐内部路由。
2. 关闭插件后不能从商城卡片打开功能，重新启用后可打开。
3. 每次用户评分为 1–5 星，按账号保存在当前设备，存储失败时给出错误提示。
4. 学生端构建包含静态注册的模块；APK 不会下载或动态执行第三方代码。
5. 新模块在商城显示审核与版本信息；未审核项目只能作为注明许可证的 GitHub 参考。

## 已知限制

当前两个内置示例是现有哦狐专注和课表的轻量入口；它们复用现有页面，不复制第三方实现。商城评分是设备本地评分，尚无全站聚合。模块启用状态按账号在设备本地保存；跨设备同步、后台动态下发和运行时插件 SDK 不属于 v1。

作者完整提交流程见[哦狐插件创作者工作流](./ohu-plugin-creator-workflow.md)。当前商城中的塔罗、星座和生日数字模块为哦狐独立编写的轻量娱乐内容；卡片展示非官方灵感来源、许可证和“仅供娱乐”边界，不复用外部牌面图片或代码。
