## 2. 当前最需要修正的问题

### 地图实现偏离了参考目标

用户要的是图4那样的地图产品：可拖动缩放的校园底图、分类地点图标、个人位置标记、浮动操作按钮、底部地点详情和导航／打卡。

当前本地实现把三张手绘参考图放在真实地图上方，手机上出现图片局部裁切和横向浏览。这是参考图展示，尚未实现目标地图；不能把它作为完成结果。

三张手绘图仅用于建筑外观、绿化、湖泊和画风参考。图上的生成文字、位置和楼号不能直接当作真实数据。现有地图地理轮廓仅有苍梧一份，通灌、宋跳需补齐并核实。

### 页面职责过于集中

`CampusMapPage.tsx` 同时处理校区、地图实例、定位、筛选、地点详情、照片、本地标记、上传审核和校园动态；页面 JSX 和 CSS 有大量长行与追加覆盖。一个视觉调整容易连带影响业务状态。

`CampusServicePages.tsx` 同时包含班车、美食、校园卡、图书馆四个页面，班车数据和通知订阅也写在页面内，后续维护成本较高。

### 素材与交付验证需要收紧

当前 `public/` 约 23 MB；四张本轮地图参考 PNG 合计约 13 MB。参考素材直接放进公开资源会增加安装包和更新包大小。应把原始参考移入文档素材区，只保留实际使用、压缩后的生产素材。

最近一次构建中，校园地图 JavaScript 块约 1.12 MB，gzip 约 310 KB。应结合真实加载情况处理地图与 PMTiles 的加载时机，避免未经测量就拆包。

当前目录不是 Git 工作区。开展地图重构前，需要先建立可回退的本地版本基线。

### 公共外壳、环境与构建入口

`PhoneShell.tsx` 的 `showFox` 同时控制登录提示和多个狐狸宿主，条件覆盖大部分次级页面。应把登录提示、静态品牌与互动拆成独立条件，互动明确限定首页和我的。

`src/lib/cb.ts` 固定了云环境；本地验收应有明确的测试环境配置，避免虚拟内容误写正式数据。地图接口中的宽泛 `any` 应逐步换成明确的查询／变更返回类型，并校验坐标、状态和图片字段，保留已有账号切换票据保护。

`npm run build` 会运行类型检查，但实际 APK 调用的 `tools/build-multiplatform.mjs` 直接执行 Vite。应把类型检查加入统一构建入口，失败时停止后续打包，再运行与变更对应的关键测试。

## 3. 地图改造方案

### 3.1 页面组成

1. **紧凑品牌页头**：阿狐小幅插画、校园地图标题、苍梧／通灌／宋跳校区切换。狐狸不遮挡地图。
2. **搜索与分类**：搜索真实地点名称；全部、美食、好玩、打卡、学习、生活。空分类显示真实空状态。
3. **主要地图画布**：用真实地理轮廓绘制校园，支持拖动和缩放；手绘与真实两种风格共享同一套坐标和地点数据。
4. **地图浮动按钮**：我的位置、校区全貌、添加地点，保持可触达且不遮住底部详情。
5. **底部地点面板**：名称、类别、审核状态、真实照片、说明、距离、导航、打卡；支持收起和关闭。
6. **动态内容**：从地图核心画布移到独立入口或下方折叠区域，减少首屏挤占。

### 3.2 地理数据与画风

- 校区选择固定为苍梧、通灌、宋跳；保留已有云端校区 ID，切换时移动地图视角，避免重复创建整个地图实例。
- 所有地点内部统一使用 WGS84；调用外部导航时按对应接口的坐标约定处理，并保留现有高德唤起逻辑。
- 真实建筑、道路、湖泊、运动场、绿地采用 GeoJSON 或现有矢量瓦片；建筑名称及校门需记录来源与核验状态。
- 手绘效果通过建筑填色、轮廓、屋顶／侧面层次、树木图标、水面纹理和柔和配色实现。三张参考图用于这些视觉细节。
- 小范围细节可以叠加经过坐标配准的图层；未经配准的整张参考图不承担定位或落点。
- 苍梧先完成一个可验证样板，确认风格和点位对齐后扩展到通灌、宋跳。资料缺失处保留真实底图，不生成虚构建筑或店铺。

### 3.3 地点与个人定位

- 地点图标使用统一的水滴标记，类别颜色和图标对应参考图；随缩放调整密度，避免名称互相覆盖。
- 用户位置采用小幅透明阿狐＋明确中心点，精度圈独立呈现。阿狐装饰不能改变实际坐标锚点。
- 点击定位立即给状态反馈，取得更准确结果后更新；拒绝、超时和粗略位置都有明确可操作提示。
- 只在用户主动操作后获取位置；切换校区和风格保留定位结果，账号切换时清除私有状态。
- 选点、上传图片、仅本机保存、提交审核继续使用现有业务链路。管理员审核通过的地点才进入公共地图。

### 3.4 建议拆分

```text
src/pages/campus-map/
  CampusMapPage.tsx          页面编排
  CampusMapPage.module.css   页面布局
  components/
    CampusSelector.tsx       三校区切换
    MapSearchFilters.tsx     搜索与分类
    MapCanvas.tsx            地图实例与图层
    MapControls.tsx          定位、全貌、添加
    PoiDetailSheet.tsx       底部地点详情
    PinEditor.tsx            选点、照片、提交
  hooks/
    useCampusData.ts         地点与加载状态
    useMapLocation.ts        定位生命周期
src/lib/maps/
  campus-config.ts          校区中心、视野、来源
  illustration-style.ts     手绘图层样式
  marker-style.ts           地点与阿狐位置标记
```

这是渐进拆分目标，先迁移地图画布和详情面板，保留现有 `src/lib/campus-map*.ts` 接口，避免一次搬动所有业务。

## 4. 整个 App 的优化顺序

| 优先级 | 工作 | 可验收结果 |
| --- | --- | --- |
| P0 | 地图目标纠偏与页面拆分 | 首屏地图占主位；移除静态覆盖图；真实点位保持对齐 |
| P0 | 统一构建检查 | 网页和 APK 都先经过类型检查，失败不进入打包 |
| P0 | 苍梧手绘地图样板 | 拖动、缩放、搜索、点位、定位、导航、打卡完整可操作 |
| P1 | 通灌、宋跳地理资料补齐 | 三校区一键切换；数据不足处明确体现，不编造内容 |
| P1 | 统一学生端公共界面 | 页头、按钮、弹层、空状态、照片展示和阿狐尺寸一致 |
| P1 | 狐狸显示与环境隔离 | 首页／我的才有互动；测试数据进入明确的测试环境 |
| P1 | 业务回归 | 游客可浏览；使用受限功能正确登录；图片、审核、点赞评论无退化 |
| P2 | 校园服务模块拆分 | 班车版本、订阅、官方入口配置从页面中独立；减少重复样式 |
| P2 | 资源与加载优化 | 原图不进入发布包；生产素材按需加载；记录前后体积与加载表现 |
| P2 | 发布前验收清单 | 学生包、管理包、热更新版本与变更范围能逐项核对 |

阿狐原则：每页首屏有一处与功能有关的品牌元素，图片透明底；详情区只按需要补小幅插画。互动仍仅放首页和我的，地图中的阿狐负责指示本人位置。
