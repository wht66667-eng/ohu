# 哦狐 App｜桌面变脸、透明表情与三种启动封面 — Codex 修改任务书

> 版本：V1 首发素材包 · 2026-10-27  
> 用途：直接交给 Codex 在**现有“哦狐”项目**中逐步修改。请先检查项目实际技术栈与目录结构，不要自行重建项目、替换现有业务代码或虚构后端接口。

## 0. 最重要的目标

在保留“哦狐”现有校园 App 功能、导航、UI 的前提下，实现：

1. **阿狐变脸素材**：同一只橙白狐狸、头顶绿色双叶嫩芽、森林绿卫衣；脸部可以极限拉伸、哭泣、暴怒、魔性狂喜，整体风格统一。
2. **按真实天数变脸**：连续登录越久越狂喜；连续未登录越久越魔性。表情根据状态阶段选取，并可在阶段内每日稳定随机。
3. **桌面展示**：手机桌面 App 图标尽量在系统许可范围内切换成对应静态阿狐脸；桌面小组件展示**累计登录天数、当前连续登录天数、连续未登录天数**及阿狐表情。iOS/Android 必须分别实现兼容策略，不能声称所有手机都能无提示自动更换桌面图标。
4. **App 打开时的三款全屏封面**：魔性怼脸、登录成就、漫画发疯；每次启动按状态智能随机，文案和天数准确，正常启动 1–2 秒，里程碑首次出现播放 3–5 秒。支持跳过、静音和减少动态效果。
5. **聊天贴纸**：复用透明 PNG，在聊天、广场评论等**已有表情入口**中展示；若项目没有此功能，先提供资源管理组件，不强行添加新社交模块。
6. **不做**宠物养成、戳脸互动、连续点击彩蛋、额外任务系统。用户已经明确取消这些方向。

## 1. 已确定的设计规则（不得擅自改变）

- 产品名：**哦狐**（OHU · MY CAMPUS）；角色名：**阿狐**。
- 角色标志：橙色狐狸、白色脸颊、深绿色上衣、头顶嫩芽；保持独立原创的固定轮廓。
- 视觉气质：奶油白 `#FFF8EB`、森林绿 `#1F5B3A`、狐狸橙 `#FF8A3D`。深色文本保证对比度。
- 动画制作路线：日常简单矢量/骨骼运动 + 特殊变脸逐帧素材；**本包 PNG 是静态素材，不是已完成的 GIF / Lottie**。
- 64 个表情包最终分布：**连续登录 20 + 连续未登录 20 + 随机魔性 16 + 隐藏成就 8 = 64**。
- 首批优先级：**连续登录 4 + 连续未登录 6 + 随机魔性 4 + 隐藏成就 2 = 16**。
- 8 个隐藏成就的最终计划：校园限定 4、节日限定 2、超稀有彩蛋 2。**本包仅有 2 款隐藏成就首发素材。**
- 文案采用“双轨”：图标、系统 UI 默认无字；全屏封面显示实时天数及短文案；聊天贴纸按业务需要添加短字／大字，文字作为 UI 图层，不烧录进原始 PNG。

## 3. 真实登录数据和天数算法（核心逻辑）

### 3.1 推荐字段

```ts
type LoginMoodSummary = {
  userId: string;
  localDate: string;            // YYYY-MM-DD，例如 2026-10-27，按用户选定时区
  timezone: string;             // 默认 Asia/Shanghai，可由设置调整
  lastActiveDate: string | null;// 最近一次已认证成功进入 App 的自然日
  totalLoginDays: number;       // 去重后的总活跃自然日数
  currentStreakDays: number;    // 截至今天，是否仍在延续的连续登录天数
  missedDays: number;           // 距最后一次活跃经过多少个未登录自然日
  moodId: string;               // 例如 miss_day_07
  coverVariant: 'face' | 'achievement' | 'comic';
  milestoneFirstSeen: boolean;
};
```

### 3.2 口径要求

- **登录一天**：当天完成认证（或保持有效会话进入前台）并成功记录一次活跃事件；同一天重复打开不增加累计天数。
- **未登录天数**：当天尚未完成活跃事件时，以用户当地**自然日**为单位，距离 `lastActiveDate` 的日差计算；例如 10 月 24 日最后一次活跃、10 月 27 日仍未打开，则未登录 **3 天**。若今天已活跃，`missedDays = 0`。
- **连续登录天数**：今日成功进入 App 且前一活跃日是昨天，则累计；若隔天缺席，新的连续登录记录从 1 开始。隔天未打开的页面不要把历史连登误称作“当前连续登录”。
- **累计登录天数**：去重日期集合的大小，长期累积，不因断签而清零。
- **时区和离线**：优先使用服务端去重记录与日期摘要；离线时标记“待同步”，不靠本地伪造增加累计天数。换时区、防止本地改系统时间作弊的策略需与现有服务端能力保持一致。
- **未曾登录 / 未有记录**：使用 `login_day_01` 风格的中性欢迎脸与“登录后开始记录”文案，不显示伪造天数或“断签 999 天”。
- **状态更新**：进入前台、认证成功、跨过当地午夜、联网同步后刷新。小组件按照操作系统更新预算推送时间线，不能保证精确午夜秒级刷新。

### 3.3 素材选择规则（目前只对应 16 款）

```ts
const LOGIN_MILESTONES = [30, 7, 3, 1] as const;
const MISSED_MILESTONES = [30, 15, 7, 3, 2, 1] as const;

function levelOf(days: number, levels: readonly number[]): number {
  return levels.find((n) => days >= n) ?? 1;
}

export function selectMood(input: {
  isActiveToday: boolean;
  currentStreakDays: number;
  missedDays: number;
  hasHistory: boolean;
}): string {
  if (!input.hasHistory) return 'login_day_01';
  if (!input.isActiveToday) {
    const n = levelOf(Math.max(input.missedDays, 1), MISSED_MILESTONES);
    return `miss_day_${String(n).padStart(2, '0')}`;
  }
  const n = levelOf(Math.max(input.currentStreakDays, 1), LOGIN_MILESTONES);
  return `login_day_${String(n).padStart(2, '0')}`;
}
```

注意：`random_*` 和 `hidden_*` 应从**当前阶段允许的素材池**中选取，不能让“未登录 30 天”的全屏封面显示“连登 7 天”的庆祝图。随机结果用 `userId + localDate + moodStage` 作稳定种子，确保**同一天桌面表情保持一致**；启动封面布局可每次打开重新抽样，但文案、情绪状态必须匹配。特殊节日优先级、考试周日期由真实活动配置驱动，不能硬编码虚构学校考试日程。

## 4. 三种全屏启动封面的实现要求

**共性：** 竖屏满版，阿狐占视觉主体 65%–85%；顶部短标题，底部显示真实日期相关数字；有安全区、可跳过按钮和减少动画开关；不能遮挡手机手势区域。`manifest.json` 中的透明 PNG 叠在背景、数字、粒子上使用。

| 模式 | 视觉/动作 | 登录成功时 | 缺席时 |
|---|---|---|---|
| `face` 魔性怼脸 | 阿狐 0.8→1.4 倍冲向镜头，眼睛嘴巴弹性夸张 | 大笑怼脸 | 哭脸 / 怒脸 / 黑化怼脸 |
| `achievement` 登录成就 | 天数卡片数字弹跳，阿狐左右摇摆，暖绿橙亮色粒子 | “连续登录 X 天” | 改为“未登录 X 天”，颜色转灰橙，不使用成功庆祝语 |
| `comic` 漫画发疯 | 漫画速度线、震动式位移（不能无上限震屏）、分镜擦除 | “我又见到你啦！” | “你 X 天没来看我！” |

**时长：**

- 普通打开 **1–2 秒**，首页准备好可跳过或立即进入；不要无故等待动画结束。
- 连登 7 / 30 / 100 天，缺席 7 / 15 / 30 天等重要节点首次解锁 **3–5 秒**；完成后同一天再次打开用短版。
- 初始绘制与加载按真实资源加载状态处理；失败时使用静态阿狐和直接进入首页，不无限循环。
- 尊重 `prefers-reduced-motion`、系统静音模式；关闭动效时展示静态封面 0–0.5 秒即可完成导航。
- 文案中所有天数必须由 `LoginMoodSummary` 生成，**不要把生成示意图中的天数当真实数据**。

### 登录页加载与切换页加载

- 登录按钮：实际请求期间按钮置为 loading；成功后显示阿狐高兴脸进入首页；失败后显示委屈表情和真实错误信息。加载状态不得写死 2 秒模拟网络进度。
- 普通 Tab 切换：≤300 ms 淡入/轻微位移即可，已缓存页面无需显示完整启动封面。真实慢加载时展示轻量狐狸骨骼屏。
- 不改变现有底部五栏：首页、服务、发布、广场、我的；不增加“养狐”“互动”等入口。

## 5. 手机桌面图标 & 小组件：原生能力边界

### iOS

- **桌面 App 图标**：使用 Apple 支持的 Alternate App Icons 机制，并预先打包允许的图标资源。具体是否出现系统提示、能否在后台自动切换由 iOS 版本和系统策略决定。**不能承诺在 App 未运行时每天自动、无提示变更图标。**
- **桌面 Widget**：优先由 WidgetKit 时间线显示每日对应静态阿狐 + 三项天数，这是展示“每日变脸”的重点方案；刷新频率由系统调度，不能常驻播放逐帧动画。
- 需要扫描仓库确认是否已有原生 iOS 工程、Widget Extension 与签名材料；没有则先交付 Web/跨端逻辑和资产接入接口，不假装原生能力已经上线。

### Android

- 可按实际架构选用预配置 `activity-alias` 等支持的桌面图标切换策略，但更新可能延迟，部分 Launcher 会出现快捷方式异常；需测试启动器、重启、图标缓存、通知跳转和登录状态恢复。
- 小组件显示当前表情和真实天数，支持系统许可的定时或工作调度更新。不要为此常驻耗电服务。

### 图标产出规范

- PNG 表情图是**透明资源**；真正的 iOS / Android 桌面图标需另外渲染成平台要求的图标文件，使用森林绿、奶油白、狐狸橙三色，不要裁掉耳朵和嫩芽。
- 图标上不要堆砌天数文字，数字放小组件；图标显示**当前阶段的阿狐大头表情**。
- 在无权限或无原生能力时显示默认图标 + 可以更新的小组件；不能因为图标不能切换而影响登录业务。
