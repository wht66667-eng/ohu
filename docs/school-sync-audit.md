# 多学校个人课表接入审计

审计日期：2026-10-20。范围：现有源码与公开入口说明，不包含其他学校的真实登录验收。

## 用户目标与当前差距

目标是在哦狐中选择学校、输入本校学号和密码，同步后在哦狐内显示个人课表。外部网页入口、学校操作说明和课表附件均不能代替这一目标。

当前只有江苏海洋大学存在已实现的个人教务适配器。其他四所学校的数据条目是官方查询指引；不能因页面样式与海大一致而改成“已接入”。用户目前没有其他学校可授权测试的有效账号，因此本次不能宣称已经验证任何一所新学校的个人登录或课表同步。

## 本轮最小修正边界

1. 保持江苏海洋大学的表单、后端、缓存和提醒流程不变。
2. 其他学校明确显示“本校课表同步尚未接通”，不展示会把凭据发向海大的输入框，不以“绑定/同步课表”描述官方网页跳转。
3. 官方入口只作为“临时查询”保留；当前浏览器环境改为同页导航，避免依赖未能打开的新窗口。导航兼容与学校系统可达性应分别验证。
4. 学校选择在本轮仅切换浏览内容；浏览其他学校说明不应清除已有海大快照或取消已安排的海大提醒。
5. 所有已准备的更新包都必须在源码修正后重新构建。新学校尚未接通这一限制要继续出现在验收记录中。

## 后续可验证的最小接入设计（尚未实现）

先适配一所能取得授权验证条件的学校，不一次性把四校标记为支持。推荐独立新增多校接口，兼容保留现有海大接口：

- 学校适配器使用服务端固定注册表，声明登录挑战类型、是否支持课表/成绩/考试、访问网络要求和实现状态。客户端不得提交任意上游地址。
- 新的挑战/查询请求显式携带 `schoolId`；服务端会话同时绑定学校、挑战和创建时间。拿另一学校的会话提交时，在接触上游前拒绝。账号限流键也包含学校，避免相同学号互相干扰。
- 各校适配器负责真实认证、学期选择与页面/数据解析，统一输出课表行与 `schoolId`、学校返回的学号、学期标识。需要额外认证步骤时明确返回挑战，不猜测登录成功。
- 返回课表时同时提供已核实的学期起点、时区、节次数量和作息来源；资料不足时要求用户确认，不能默认海大时间。
- 客户端引入不可变的请求上下文 `{ appUid, appRevision, schoolId, bindingRevision }`。请求返回、存储和排提醒前均校验上下文，学校/账号切换后的旧结果不得写入。
- 凭据、快照、成绩/考试、作息、日历修改按 App UID、学校、绑定账号和学期进行隔离。旧数据只走海大兼容读取，不默认认领给其他学校。
- 先明确同一 App 账号是“一份当前激活课表”还是“多校同时提醒”。前者切换激活绑定时原子替换提醒；后者需重新设计原生计划的上下文和通知 ID 分配。仅切换浏览学校不等于切换提醒绑定。

## 必须取得的后续条件

真正完成某校适配，至少需要下列条件之一：学校提供可用的正式接口规范和授权测试环境；或持有有效本校账号的使用者在本地自行登录，并同意提供去除个人信息的结构样本及结果核对。密码、完整会话 Cookie 和登录票据不应发到聊天或写入项目样本。

同时需要：

- 从哦狐实际运行位置（云端代理或手机）能合法到达学校认证及教务服务；校内网入口不能因电脑偶然可达就假定云端可达。
- 核实登录跳转、验证码/额外认证、成功标识、失败语义、当前学期与个人课表响应；公开登录页只能证明页面存在。
- 一份去标识化的有效课表样本和校历/作息资料，用于周次、单双周、连堂、空课表及跨学期解析测试。
- 至少一次真实账号端到端核对：学校原课表与哦狐逐项一致，并验证重启/离线显示与提醒时间；模拟数据通过不能代替这项验收。

现阶段可继续核验公开入口、设计隔离机制、修正误导状态。没有上述条件时，不应收集其他学校密码、不应猜测认证接口，也不能将个人课表同步标记为完成。
