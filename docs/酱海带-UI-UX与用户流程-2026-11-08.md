## 一、样本与总体印象

| 项目 | 值 |
|---|---|
| 应用名 / 包名 | 酱海带 / `com.jianghaidai.campus` |
| 版本 | 0.8.1（versionCode 1028） |
| 技术栈 | Flutter（`libapp.so` AOT；包内符号 `package:jianghaidai_campus/...`） |
| 最低 / 目标 SDK | 24 / 36（Android 16） |
| 权限 | 网络、通知、精确闹钟、安装未知应用、开机自启、震动、唤醒锁、外部存储（≤29） |
| 登录态 | 实测设备上已登录（显示「王昊天 / 2023120448」），成绩/课表/考试为缓存数据 |
| 社区 | 独立论坛 `bbs.jianghaidai.com`，用校园账号一键登录 |

**总体印象（用于对比哦狐）**

- 结构是「首页 / 课表 / 社区 / 成绩 / 我的」五大区，**成绩区把课程、公选、体测、PU 收进同一个页面的四个子 tab**，比哦狐的「多入口分散页」更聚合。
- **登录体系分层清晰**：校园账号（WebVPN + CAS）是主线，体测、PU、学习通都是「绑定/连接」式独立账号，且明确写了「已绑定/自动续登/断开清除」。
- **口径说明写得非常细**（公选 H/R/Z/G 分类上限、PU A/B/C/劳动、两源不相加），这类文案对减少用户误解很有参考价值。
- **数据状态透明**：成绩页顶部常驻「刷新失败，正在显示本地成绩，非实时数据 · 更新于 …」，空/旧数据不伪装成实时。
- **桌面组件**是它的差异化：我的 → 桌面与锁屏（课程、教室与考试，抬眼可见）。

## 三、页面详解

### 3.1 首页（实测）

从上到下：

| 区块 | 内容（实测文案） |
|---|---|
| 顶部问候 | `11月8日 周日 · 第 10 周`、`夜深了，王昊天`、`打开我的页面` |
| 下一次课程 | `下一次课程 · 2天后 8:00` / 课程名 / `08:00-09:40 · 第 1–2 节` / 教室 |
| 学习中心 | `最近记录`、`最近记录中暂无待办` |
| 我的计划 | `记下作业，也留出自己的时间` + `添加任务或安排` |
| 今日安排 | `完整课表，查看今日安排`；`今天没有课程` 空态 |
| 近期考试 | `18天后 海洋地理信息系统 11月26日 15:00-17:00 C文通126` 等横向卡片（4 张，可横滑） |
| 社区新动态 | `进入社区，查看社区新动态`；连接失败时显示 `社区暂时无法连接` + `重试` |
| 快捷功能 | `校历` / `课程与考试提醒` / `考试安排`（横向格子） |

**观察**

- 首页把「课程 + 计划 + 考试 + 社区」四类信息压缩在一屏，信息密度高，但区块之间的视觉权重接近。
- 考试卡用「N天后 + 日期时间 + 教室」三行，倒计时放在最前面，扫读效率高。
- 社区区块失败时有就地重试，不阻塞其他区块。

### 3.2 课表（实测）

- 顶部工具：`添加课程或安排`、`切换为列表视图`、`课表选项`。
- 周次条：`第 10 周`、`11月2–8日`，可横向切 7–16 周，当前周标「本周」。
- 网格：7 天列（周一…周日，今天为周日并高亮），左侧节次列 `1…8`，每节两行时间（如 `08:00 / 08:45`）。
- 课程块按节次纵向排布（本次为第 10 周，实测网格内课程块未展开文本）。
- 我的 → 分享课表：分享课表图片或导出到系统日历（推断自「我的」条目）。
- 我的 → 桌面与锁屏：课程、教室与考试以小组件形式展示（自述文案）。

### 3.3 社区（实测）

- 顶部：`搜索社区`、`社区账号`。
- 引导卡：`校园账号快速登录社区 / 校园账号已登录 · 一键进入社区 / 无需申请校园邮箱或设置新密码`。
- 首次说明弹层：`欢迎来到酱海带社区`，正文强调「新生答疑、校园生活、经验分享」「游客可以随便看；登录社区账号后就能发帖提问、回复和点赞」「提问前不妨先搜一搜」。
- Tab：`最新 / 热门 / 待回答`；右侧 `分类`。
- 列表离线态：`社区暂时无法连接` + `重试`。
- 页脚：`社区由 bbs.jianghaidai.com 提供`。
- 右下/底部 `发帖` 入口。

**观察**：社区与校园账号打通（CAS 换社区会话），不要求额外注册；游客与登录用户的能力边界用一句话说清。

### 3.4 成绩（实测，重点）

**页面头部**

- 标题 `成绩` + 学期选择器（`选择学期，当前2026年春季学期`）。
- 子 tab（可横向滚动）：`课程成绩` / `公选进度` / `体测成绩` / `PU 成绩`。
- 常驻缓存条：`刷新失败，正在显示本地成绩，非实时数据 · 更新于 11月7日 13:38`。

**3.4.1 课程成绩**

- 统计卡：`平均绩点 3.62`、`平均分 75.0`、`总学分 30.6`、`课程数 15`。
- 筛选：`全部 / 必修 / 选修`；排序：`默认排序`。
- 课程行：课程名 + `必修课 · 2 学分` + 成绩 + `绩点 0.0`；点击进成绩详情。
- 学期分组标题：`2026年春季学期 · GPA 3.62`。

**3.4.2 公选进度**

- 右上入口：`查看公选课毕业要求说明 / 毕业要求`。
- 总进度：`有效学分 4.0 / 要求 8.0`、`1 / 4 类达标`，副文案「每类最多按 2 学分计入总进度，超额学分不能跨类别抵扣」。
- 类别卡（每类一张）：
  - `H 海洋知识类` · `待完成` · `已通过 1.0 / 2.0 学分` · `还差 1.0`
  - `R 人文素养类` · `已达标` · `已通过 4.0 / 2.0 学分` · `要求已满足`
- 类别内课程行：`课程名 · 课程代码 · 学期 · 学分` + `成绩（优秀/…）` + `计入学分`。
- 筛选：`全部类别` / `仅看未达标 (3)`。
- 无障碍文案里带进度百分比（50/100），说明类别卡本身有进度条。

**3.4.3 体测成绩**

- 头部右侧：`管理体测账号 / 已绑定`（体测账号与校园主账号绑定）。
- 子 tab：`本次` / `历年` / `标准`。
- 当前学年卡：`2026–2027 学年`、等级 `不及格`、`总分 0`、`加分 +0`、`1 / 7 项已完成`。
- 项目列表（本次）：
  - `视力` · `不计入体测总分` · `左 0.0 · 右 0.0`
  - `BMI` · `尚未测试 · 权重 15%` · `—` · `计入总分` · `暂无评价`
  - `肺活量` · `尚未测试 · 权重 15%`
  - `50米跑` · `尚未测试 · 权重 20%`
- 观察：每项都显式写出「权重 / 是否计入总分 / 状态」，比只显示分数更不容易误解；「管理体测账号（已绑定）」把独立账号这件事做成了可管理的对象。

**3.4.4 PU 成绩**

- 本次未能在 MuMu 上展开（子 tab 超出屏幕且不响应横滑），但从包内字符串可确认其结构（见第五节）：
  - 优先显示 PU 官方成绩、分类与明细；没有官方数据时才用校园档案；
  - 支持 `PU 密码连接`、`PU 密码重新连接`、自动续登；
  - 明确 `PU 账号与当前校园学号不一致，请使用本人的 PU 账号` 等校验文案。

## 四、登录与取数体系（由界面 + 包内字符串还原）

### 4.1 主线：校园账号（WebVPN → CAS → 正方）

- 网关：`webvpn.jou.edu.cn:58888`；门户：`portal.jou.edu.cn`；教务：正方 `zf`；选课：`zfxk.jou.edu.cn`。
- 包内符号可见：`core/auth/webvpn_url.dart`、`features/course_selection/repository/webvpn_course_selection_repository.dart`、`features/course_selection/auth/legacy_zfxk_rsa_cipher.dart`。
- 相关界面文案（节选）：
  - `WebVPN → 统一认证 → 正方会话，无需额外选课密码`
  - `WebVPN 登录失败，请检查学号和 WebVPN 密码。`
  - `WebVPN 校外访问通道。2023 级初始密码为身份证后八位；2024 级及以后为身份证后八位@Jou。`
  - `ZF 会话学号不一致`、`WebVPN 教务会话与选课 owner 不一致`
- **推断**：教务/选课不要求「选课密码」，而是用 WebVPN + CAS 会话换正方票据；老选课系统（zfxk）用 RSA 加密口令。

### 4.2 体测（tice）

- 入口域名：`http://tice.jou.edu.cn:8080/student/Historyhealth.jsp`、`/student/queryHealthInfo.jsp`、`/student/studentFrame.jsp`。
- UI 里有「管理体测账号 / 已绑定」——体测密码被当作独立凭据绑定到当前校园账号。
- 失败文案：`WebVPN 暂时无法访问体测系统，请重新登录后重试`。
- 观察：与哦狐一致（同一套学校系统），但酱海带把绑定关系放在成绩页顶部，可管理、可重绑。

### 4.3 PU（口袋校园）

- 独立账号 + 独立密码；相关文案（节选）：
  - `PU 口袋校园的密码`
  - `PU 密码加密保存在系统安全存储，仅用于自动续登；断开连接时一并清除。关闭后只保存本次会话。`
  - `PU 密码连接` / `PU 密码重新连接后，即可继续更新。`
  - `PU 账号与当前校园学号不一致，请使用本人的 PU 账号`
  - `PU 查询账号与当前校园账号不一致，请重新登录校园账号`
  - `PU 登录已失效，请重新连接 PU 账号`
  - `PU 存在学分转置，当前明细暂不能核对转置后的完整结果，请查看官方成绩单`
  - `A、B 类和劳动教育均优先使用已获取的 PU 官方成绩、分类及明细，没有该类官方数据时才使用校园档案。官方记录使用独立的 PU 密码连接，两源不相加。`
  - `C 类存在分类遗漏，与官方记录分别展示，不相加、不用于计算完整劳动学分。`
- 观察：这是酱海带做得最细的一块——**凭据生命周期（自动续登/断开清除/只保存本次会话）+ 数据口径（官方优先、两源不相加）+ 异常态（失效/不一致/转置）**三件套齐全。

### 4.4 学习通（超星）

- 字符串可见：`notice.chaoxing.com`、`/pc/notice/getNoticeList`、`/pc/notice/myNotice`、`mooc2-ans.chaoxing.com/.../coursenotices`、`LearningNotice`、`urgentNotices`、`noticesScanned`、`学习通记录尚未同步`、`本次作业 30%`。
- 推断：学习通以「通知/作业/成绩」聚合进学习中心，而不是单独一个「学习通页」。

### 4.5 实践系统 / 体测实践

- 域名：`practice.jou.edu.cn`；符号：`features/practice/practice_client.dart`、`PracticeParser`、`practice_record_rows`（本地 SQLite 表）。
- 文案：`PracticeSession(sidLen=…)`、`must call enter() before fetching practice pages`、`practice:cas-servicer`。
- 推断：实践/体测实践数据走 SQLite 缓存 + 增量刷新，失败有 `PracticePartialRefreshException` 之类的局部刷新语义。

### 4.6 社区（bbs.jianghaidai.com）

- 接口：`https://bbs.jianghaidai.com/jou-campus-auth/campus-relay/sessions.json`、`/jou-campus-auth/campus-relay/challenge.json`。
- 其自述的隐私设计（原文，节选）：
  - `App 才会将学号和门户密码经 TLS 固定直连论坛源站，交学校 CAS 验证；不会发送姓名、成绩或 Cookie。`
  - `Cloudflare/CDN 只转发加密的登录信息，论坛源站解密后短暂处理并转发密码，不写入数据库、Redis 或日志。验证后会立即撤销 CAS 临时凭据，无法确认撤销就中止。`
  - `服务器可能将部分内存交换到磁盘，密码或密钥可能随之落盘；进程内存无法保证逐字节清零。`
  - `App 内完成，密码只提交给论坛`
- 观察：把「做不到的保证」也写出来（内存交换、撤销不确定就中止），属于高信任度文案；对哦狐的登录/社区文案有直接参考价值。

## 五、UI/UX 特征总结

1. **聚合式成绩中心**：四个子 tab（课程/公选/体测/PU）共用学期与刷新状态，减少跳转。
2. **状态透明**：缓存时间、非实时提示、失败重试都在页面上，不藏在设置里。
3. **口径前置**：公选 H/R/Z/G 上限、PU 与档案不相加，都写在数字旁边，而不是帮助页。
4. **独立账号管理化**：体测「管理体测账号 · 已绑定」、PU「密码连接 / 自动续登 / 断开清除」，把密码从「一次性输入」变成「可管理的连接」。
5. **社区与校园身份打通**：游客可读、登录可写；用「无需申请邮箱/密码」降低门槛。
6. **桌面组件**：课程/考试/教室上升到系统桌面，属于留存型功能。
7. **文案颗粒度**：大量「为什么/边界/失败后怎么办」的解释性文案，信息密度高，适合愿意读的用户；对新用户可能偏重。

## 六、与哦狐的对照（供优化决策）

| 维度 | 酱海带（v0.8.1） | 哦狐（1.2.155 开发中） |
|---|---|---|
| 主框架 | 左侧 5 项导航（首页/课表/社区/成绩/我的） | 底部 5 位 TabBar（首页/服务/发布/广场/我的）+ 侧边菜单 |
| 成绩聚合 | 一个页面 4 个子 tab | 成绩中心 + 多个独立页面（课程/公选/PU/体测/素质拓展） |
| 体测 | 子 tab；「管理体测账号 · 已绑定」 | 独立页；1.2.155 起页内独立登录卡 |
| PU | 子 tab；官方优先、自动续登、两源不相加 | 独立页；1.2.155 起页内独立登录卡 + 手动登录兜底 |

## 七、可借鉴点与给哦狐的优化建议

### 可以直接借鉴

1. **成绩页聚合**：把「课程成绩 / 公选进度 / 体测 / PU」收进同一页的子 tab，共用学期与刷新状态，减少「哦狐多入口」的迷路感。
2. **常驻数据状态条**：在成绩/体测/PU 页顶部固定一条「非实时 · 更新于 …」；哦狐目前只在卡片底部写时间，容易被忽略。
3. **独立账号管理化**：体测「管理体测账号 · 已绑定」、PU「连接 / 自动续登 / 断开清除」；哦狐 1.2.155 已有独立登录卡，可再补「已连接状态 + 解绑入口」。
4. **异常态文案清单**：失效、账号不一致、分类遗漏、学分转置等场景，酱海带都有一句话解释 + 下一步；建议哦狐整理同类清单。
5. **社区身份打通**：学号/校园账号一键进社区，游客可读；如果哦狐社区要拉新，这条路径更短。

### 需要避免或改进（对照后看哦狐）

6. **信息密度**：酱海带首页/成绩页信息很密；哦狐的卡片式留白更多，但同步入口分散——建议在「聚合」和「留白」之间取中间值：一页放关键数字 + 折叠明细。
7. **左侧 Rail 在手机上**：酱海带的左侧导航在 MuMu 上占掉 140px 宽；手机竖屏空间更紧，哦狐的底部 Tab 更适合单手。
8. **解释性长文案**：哦狐已有大量「说明」卡，注意折叠，避免每次同步都要求用户阅读。
9. **缓存与刷新**：酱海带的「刷新全部数据」是单一动作；哦狐 1.2.155 拆成多项独立按钮后，建议提供一个「全部更新」的聚合入口（现有「更新数据」可复用），并明确哪些源会被更新。
10. **体测标准**：酱海带体测有「标准」子 tab；哦狐当前标准页提示「学校评分标准未接入」——可参考其呈现方式（国家线 vs 校线的区别写清楚）。
